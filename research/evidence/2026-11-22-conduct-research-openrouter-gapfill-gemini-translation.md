# OpenRouter deep dive - gap fill for Google Gemini: translations that exist in open-source projects for the Gemini features OpenRouter documents no chat-completions field for

- What was read: source code at pinned commits for LiteLLM, the Vercel AI SDK Google provider, Gemini CLI, agentgateway, Bifrost, Portkey, Pydantic AI, LangChain's Google package, new-api, one-api, and Google's own `python-genai` and `js-genai` SDKs; the projects' own documentation pages; Google's live Gemini API pages, API reference, Terms of Service, and Google Cloud's thought signature and migration pages; five public issue and pull request pages; and the four first-wave evidence files for Gemini, LiteLLM, open-source gateways, and unified SDK model layers.
- How many sources: 38 (listed in the Sources table), giving 68 evidence items and 21 candidate matrix rows plus one feature-by-project table.
- Read date: 2026-11-22 for every source. Every item here is `Filled` (the project is named) or `Vendor-documented`, except one item (GX49) that quotes OpenRouter's Gemini 4 guide for comparison and one workspace check (GX67). A fill shows that a translation exists and what it costs. It never shows what OpenRouter does.

### Feature by project: where the handling sits

Cell values. **Inside**: handled wholly inside the translator or client library, with a neutral request or no request at all. **Opaque**: the reply holds a field the caller must store and return without reading it. **Option**: the caller passes a Gemini-specific option or tool entry, or reads a Gemini-named reply field. **Left out**: the project drops the feature or cannot reach it on that route, as far as a search of the code read shows. A short note in brackets names the field. "Google's route" is Google's own OpenAI-compatible route as documented (first-wave items GG25, GG97 to GG99); a feature its page does not list is marked left out.

1. **Do thought signatures move between Google AI Studio and Vertex AI? (OQ10)** Rejection in both directions is reported by a Vercel AI SDK user (2026-04-07), by Pydantic AI's maintainers with a claim of live requests (2026-10-27), and by LiteLLM's merged fix with a claim of live verification (2026-11-03). Google's pages, read today, are silent (GX30 to GX35, GX68). The dated reports all point one way, but none is a Google statement and nothing was run here, so this stays unresolved. The 2026-09-20 Runvil report ("same endpoint only; AI Studio to Vertex is HARD") agrees with the three reports.
2. **Finish reasons.** `RECITATION` is `content_filter` in six projects and `stop` in Portkey's strict map. `MALFORMED_FUNCTION_CALL` is `stop` in four gateways, `error` in three SDKs, an HTTP 500 in LiteLLM when the reply is empty, and a retry in Gemini CLI. `CONTINUATION` is `length` (LiteLLM, Vercel, Pydantic AI), `stop` (agentgateway, Portkey strict), `continuation` (Bifrost), or `other` (LangChain) (GX12). No source says which is right; they are design choices.
3. **Which JSON Schema keywords `responseJsonSchema` accepts.** Google's page lists a keyword set that does not name `$ref`, `$defs`, `anyOf`, or `const` (GX36). LiteLLM's comment says it "accepts standard JSON Schema as-is, including $ref, $defs, anyOf, etc." and agentgateway's says it "accepts raw JSON Schema ($defs/$ref/anyOf/additionalProperties)" (GX38, GX41). LangChain's docstring says "The Google GenAI SDK automatically transforms schemas", including "Inlining `$defs` definitions" (GX45), which suggests the SDK rewrites before sending. Vercel and Pydantic AI both say `const` is not supported and rewrite it; LiteLLM sends it unchanged (GX38, GX39, GX44). Not tested here.
4. **Search tools mixed with function tools on Vertex.** LiteLLM's comment says "Vertex AI does not support mixing function declarations with search tools" and drops search unless the caller sets `include_server_side_tool_invocations` (GX15). The Vercel AI SDK sends both tool kinds on Gemini 3 and sets `includeServerSideToolInvocations` only when the provider is not Vertex (GX17). Bifrost sets the flag whenever the caller asks (GX19). Whether Vertex accepts the flag is not settled by these sources.
5. **Vercel's caching docs contradict their own example.** The sentence says the example uses `gemini-3.8-flash` because "Gemini 4 Argon supports implicit caching only", and the code under it sets `const model = 'gemini-4-hydrogen';` (GX63).

The first-wave Gemini file quotes a rule from the same reference that allows "underscores and dashes" (GG87). Both are on the live reference; they describe different fields (the declaration and the call).
