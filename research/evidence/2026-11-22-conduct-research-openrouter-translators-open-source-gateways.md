- How many sources: 60 source keys. 49 are gateway source (48 file groups across seven repositories, plus one npm package). The others are one key for public metadata of nine repositories, five issue reports, one OpenRouter page, three workspace documents, and one activity check of two repositories that were set aside.
- Read date: 2026-11-22. Every item is `Filled` (a fill from the named project) unless it says `OR-inferred`. A fill shows how that project solves the thing. It does not show what OpenRouter does. The "Native rule" cells rest on what the gateway code and its comments say about the vendor, plus the 2026-11-17 workspace report. I did not read vendor documentation pages for this file.

## Conflicts and disagreements

Between the gateways:

- **Does `prompt_tokens` include cached tokens?** agentgateway adds cache reads and writes into `prompt_tokens` (J16). Portkey reports Anthropic's `input_tokens` alone and adds the cache counts only into `total_tokens` (J80). A caller that computes cost from `prompt_tokens` gets different numbers from the two.
- **Does `completion_tokens` include reasoning tokens for Gemini?** Bifrost adds `thoughtsTokenCount` into `completion_tokens` (J44). agentgateway's comment says Gemini's OpenAI-compatible endpoint "leaves reasoning out of `completion_tokens` but counts it in `total_tokens`" and it corrects for that with a maximum (J-s3, `types/completions.rs:286-292`).
- **Finish reasons for the same native value.** Anthropic `refusal`: `content_filter` in agentgateway and Envoy, the raw string `refusal` in Bifrost, `stop` in Portkey's strict map. Anthropic `pause_turn`: `stop` in agentgateway and Portkey, `pause_turn` in Envoy and Bifrost. Gemini `RECITATION`: `content_filter` in agentgateway and Bifrost, `stop` in Portkey, `recitation` in Envoy (J17, J45, J78, J90).
- **Effort to budget.** agentgateway uses fixed budgets (`high` is 4096). Bifrost uses a share of `max_tokens` (`high` is 0.80 of the room above the minimum). For the same request the two send different budgets (J13, J42).
- **The validator-bypass string for Gemini.** Bifrost and Envoy send `skip_thought_signature_validator`. new-api sends `context_engineering_is_the_way_to_go`. Envoy's comment calls its value "Google's documented compatibility escape". I did not open Google's page (J32, J89, J96).
- **The neutral name for a cache mark.** agentgateway reads OpenAI's `prompt_cache_breakpoint` on chat-completions parts. Bifrost, Portkey, and Envoy read Anthropic's `cache_control` on the same parts (J15, J43, J75, J92).

With the local Runvil documents:

- **Tool id rewriting in agentgateway.** Appendix B of the 2026-11-17 Anthropic Messages report credits agentgateway with rewriting a tool id that fails Anthropic's pattern. At commit `888badbb` the chat to Messages path copies the id (`id: call.id.clone()`, `conversion/messages.rs:485`), and a text search of that file for a sanitizing step found nothing. Bifrost does rewrite, by hash (J34). I cannot say what commit `bdb36de0` did. At today's commit the rewrite is Bifrost's. Confidence: medium.
- **"A client that reads `reasoning_details` also works against OpenRouter and Bifrost"** (the same report, section 2). Reading works, since the name and the three type strings match. The entries are not interchangeable: OpenRouter tags each with `format`, Bifrost's entries end at `data`, Bifrost puts a Gemini signature in the `signature` field of a `reasoning.encrypted` entry, and Bifrost sends reasoning text only when its upstream is OpenRouter (J27, J31, J52).
- **claude-code-router's transformers.** The same report read claude-code-router at `da96d5d`. At today's commit the repository holds no transformer code, and the translation lives in the npm package `@the-next-ai/ai-gateway` (J2). A reader who follows the old citation finds a different layout.
- **LC17** calls `prompt_tokens_details.cache_write_tokens` "the extension name OpenRouter uses". Bifrost's source says "OpenAI's Responses API reports cache writes under cache_write_tokens" and calls it "OpenAI's field name for cache writes" (J44). If Bifrost is right, the name is OpenAI's own and three open gateways already write it. I did not check OpenAI's documentation, so this is a flag, not a correction.
- **LC1, LC8, LC11, LC12** are supported from the client side: three OpenRouter routes in one path pattern (J57), the `provider` field names (J58), `finish_reason: "error"` in a stream (J67), and a choice on the usage chunk (J66).

This shows the translation is common practice. It says nothing about OpenRouter's own code.
