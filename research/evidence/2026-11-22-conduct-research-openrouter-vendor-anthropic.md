# OpenRouter and Anthropic vendor-native features - signed thinking and prefix binding, thinking modes and effort, cache breakpoints, server tools and pause_turn, compaction, citations, files, batches, tool search, removed sampling parameters, stop reasons, beta headers, errors, and Bedrock and Vertex differences

- **What was read:** the local mirror of OpenRouter's documentation (the six Claude migration guides, reasoning tokens, prompt caching, provider selection, server tools, errors, service tiers, batch, files, the changelog), OpenRouter's OpenAPI spec, its public model catalog and six per-model endpoint lists, its official AI SDK provider source, 46 live pages of Anthropic's documentation (81 were downloaded) plus the Claude Code gateway guide, and LiteLLM and agentgateway at pinned commits. The workspace report of 2026-11-17 on Anthropic's Messages API was the starting point.
- **How many sources:** 91 (36 OpenRouter, 47 Anthropic, 2 gateway source repositories, 6 workspace documents).
- **Read date:** 2026-11-22 for every source. Nothing was run against a model, and every read was public and unauthenticated.

## Candidate matrix rows

OpenRouter may include a standard HTTP `Retry-After` response header", and the mirror mentions `X-RateLimit-*` only "on free-model and key-management errors". No page mentions `anthropic-ratelimit`. Anthropic's gateway guide asks for the opposite: "`retry-after` | Return integer seconds rather than an HTTP date." and "`x-should-retry` | Pass the upstream's value through unchanged." Sources: AN-s65, AN-s16, AN-s86, AN-s36. Basis: Vendor-documented, OR-documented, and OR-inferred for the absence of Anthropic's headers.

### N. Other fields that exist on the Messages route only

- **AN98** `safeguards` and task budgets. OpenRouter's Messages schema has `safeguards[]` ("A server-side safeguard Anthropic evaluates alongside the completion", example type `dangerous_tool_use`) and returns `safeguard_results`. The changelog dates the request field to "September 22, 2026". Armor guide: "A `safeguards` entry is Anthropic's field and is read only on the Messages API. On Chat Completions or Responses it does not arm Armor; a proxy that forwards a Claude Code request onto those APIs (LiteLLM does) gets no evaluation and no error." and "When the request reaches an Anthropic endpoint that supports the beta, Anthropic's classifier evaluates the call and its verdict is passed through. On every other endpoint, Armor evaluates." Claude Code's guide names the pair: "The `anthropic-beta` value and `safeguards` field for auto mode's [server-side classifier review]". Task budgets: the schema's `output_config.task_budget` (`type: "tokens"`, `total` at least 20000, `remaining`) is described as "The model sees a countdown of remaining tokens and uses it to prioritize work and wind down gracefully." Anthropic lists task budgets as beta on five platforms (Bedrock is not among them). Sources: AN-s30, AN-s26, AN-s23, AN-s86, AN-s84. Basis: OR-documented and Vendor-documented.
- **AN99** The Messages route is Anthropic's shape plus OpenRouter fields. The spec describes `MessagesMessageParam` as "Anthropic message with OpenRouter extensions". The request adds `models`, `plugins`, `provider`, `route`, `session_id`, `stop_server_tools_when`, `deferred_tools`, `trace`, `user`. The response adds `provider`, `openrouter_metadata`, `usage.cost`, `usage.cost_details`, and `context_management`. Streaming: "the Messages API (`/api/v1/messages`) reports it in the `message_delta` event before `message_stop`" (usage), and `openrouter_metadata` arrives "as part of the terminal `message_stop` event (Anthropic Messages)". Tier labels: "the Messages API returns `service_tier: "standard"` where the Chat Completions and Responses APIs return `"default"`." Reasoning on this route is not limited to Claude: "OpenRouter normalizes both into the unified `reasoning` parameter, so they work on every reasoning model, not only Claude." Sources: AN-s30, AN-s27, AN-s28, AN-s19, AN-s7. Basis: OR-documented. This confirms survey claim LC1 for the Messages surface.

## Conflicts and disagreements

**Between OpenRouter's own sources**

- **Default effort on Opus 5.5.** The Claude 5.5 migration guide says requests with no effort "run at Anthropic's default of `medium`", and Anthropic says the same (AN24). The public catalog reports `default_effort: "high"` for `anthropic/claude-opus-5.5` and for `~anthropic/claude-opus-latest` (AN25). The guide and Anthropic agree, so the catalog value is the likely error. A client that pre-selects the catalog's default would send `high` where the model's own default is `medium`.
- **Forced tool choice on Haiku 5.5.** The migration guide says "Forced tool use still works on Haiku 5.5", and Anthropic's list of models that refuse it does not include Haiku 5.5 (AN67). The endpoints API reports `"required": false, "function": false` on all five Haiku 5.5 endpoints (AN68). The guide and Anthropic agree, so the endpoint flag is the likely error, or it reflects a routing rule the docs do not describe.
- **Sampling parameters: ignored or rejected.** The Opus 4.7 and Sonnet 5 guides say the parameters "will be silently ignored". The Claude 5.5 guide says Haiku 5.5 "rejects" non-default values and tells callers to remove them, without saying whether OpenRouter drops them first (AN66). Anthropic's rule depends on the API version: non-default values fail on these models under `2023-06-01`, and every value fails on every model under `2026-10-21` (AN65). The docs do not name the version OpenRouter sends, so the two guides cannot be reconciled from documentation alone.
- **What `reasoning.enabled: true` means.** The reasoning guide says it "Enables reasoning at the "medium" effort level with no exclusions." The Claude 5.5 guide says a request with no effort is "sent without one" so the model default applies, which is `high` on Sonnet 5.5. The model-specific guide is newer and more specific.

**Between OpenRouter and Anthropic**

- **Which thinking is account-bound.** Anthropic names four models: "Claude Fable 5.2, Claude Mythos 5.2, Claude Sonnet 5.5, and Claude Haiku 5.5" (AN5). OpenRouter's guides describe account-bound routing for Sonnet 5.5 and Haiku 5.5 only (AN11), and the Fable 5.1 guide says of Fable 5.2 only that "The same five changes apply". Fable 5.2 has four OpenRouter endpoints (Vertex, Azure, Anthropic, Anthropic fast), so the case can arise. Anthropic is the authority on the binding. Whether OpenRouter routes Fable 5.2 replays the same way is undocumented.
- **What counts as one account.** Anthropic says the account is "Your organization" on the Claude API, Claude Platform on AWS, Google Cloud Anthropic-managed, and Foundry alike, for all four models. OpenRouter says Sonnet 5.5 replays can move among "Anthropic, Claude Platform on AWS, and Azure" as one account group, while Haiku 5.5 replays stay "on the provider that produced them". Both can be true if OpenRouter's own accounts are linked differently per model, but the docs do not say why the two models differ.
- **Fast mode providers.** OpenRouter: "Fast mode is only served by the Anthropic first-party provider, since other providers (e.g. Amazon Bedrock, Google Vertex) do not support it." Anthropic's fast mode page lists Google Cloud Google-managed and Foundry as supported platforms, and its pricing page says fast mode for Fable 5.2 "is also available on [Claude Models on Google Cloud (Google managed)]" (AN84). The OpenRouter sentence is accurate about what OpenRouter offers (only `anthropic/fast` endpoints exist) and out of date about Vertex.
- **Beta header for strict tools.** OpenRouter says a caller "must explicitly pass the `structured-outputs-2025-11-13` header" or the `strict` field is stripped. Anthropic says "beta headers are no longer required" and keeps that header only for the deprecated `output_format` parameter (AN76, AN77). OpenRouter's rule describes OpenRouter's own gate, which now lags the vendor.
- **Beta header for tool changes.** OpenRouter's Opus 5 guide names `mid-conversation-tool-changes-2026-07-01`. Anthropic now says "Where both work on your platform, send `inline-tools-2026-09-15`" (AN64). OpenRouter attaches the header itself, so a caller is not affected.
- **Web search on Vertex.** Anthropic lists the basic web search tool as available on Google Cloud Google-managed (AN39). OpenRouter's endpoint data lists no native web search on `google-vertex/global`, and its batch page says "Google Vertex rejects web search tools." (AN40). OpenRouter's statement describes what it routes.
- **Sonnet 4.5 context window.** Anthropic: "Other Claude models, including Claude Sonnet 4.5 (deprecated), have a 200k-token context window." OpenRouter's catalog lists `anthropic/claude-sonnet-4.5` at `context_length: 1000000` with a price override above 200,000 prompt tokens, and 200,000 on the Azure endpoint (AN60, AN61). The catalog reflects an older long-context option that Anthropic's current pages no longer describe. Not resolved here.
- **Native tool search providers.** Anthropic lists tool search as available on Amazon Bedrock ("Available through the InvokeModel API, not the Converse API."). OpenRouter's list of endpoints that defer natively is "Anthropic, Vertex, Azure Foundry and Claude Platform on AWS", so Bedrock gets OpenRouter's emulation (AN63).

**Inside Anthropic's documentation**

- **Seven stop reasons or eight.** The API reference and the stop-reasons page list seven values. The compaction guide's code tests `response.stop_reason == "compaction"`, an eighth (AN50, AN71). OpenRouter's Messages schema enumerates all eight (AN45).

**Against the local Runvil documents**

- **The 2026-11-17 report on the Messages API.** Every point re-checked today held: the prefix check outcomes, the per-model thinking table, the `2026-10-21` removals, the error types, the caching limits. - **LC3** ("Unsupported parameters are silently ignored, not rejected") needs exceptions for Claude.
