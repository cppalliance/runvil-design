# Workshop: How to Decompose an IDE Core into Crates

Report type: evaluation / review. It judges Workshop against 6 popular codebases sharing the extensible-editor/IDE technique, and prescribes idioms to adopt, in payoff order.

## Executive summary

Workshop has the substrate of a serious IDE core and the shell of a monolith: the wire protocol, delivery semantics, error discipline, and lifecycle are already field-grade, but the server is one 18k-line crate with subsystems hand-wired into a god-struct - exactly the shape every reference outgrew before scaling. All six references converge on the same three mechanisms Workshop lacks: subsystems that register themselves through a low-level registry instead of being named by the composition root, a one-way crate/layer graph enforced mechanically, and per-subsystem state behind narrow handles. The top finding - a dependency-inversion registry in a bottom crate - pays twice: it kills the hand-wiring today and makes the crate split possible without cycles tomorrow.

### Key findings

1. **Subsystems should self-register through a proxy registry owned by a bottom crate - the pattern all six references use.** Zed's `ExtensionHostProxy`, VS Code's `registerSingleton`, Theia's `ContainerModule` contribution points, rust-analyzer's `handlers::all()`, Helix's `register_hook!`, and ox's convention tables are six forms of one mechanism: the composition root stops naming subsystems. Confidence: high.
2. **Split workshop-server into one-way layer crates with written per-crate invariants.** rust-analyzer, Helix, Zed, and ox all keep narrow interface crates above deep implementation crates, with the layering written down as invariants. Confidence: high.
3. **Enforce the graph mechanically - invariants as tests, not reviewer vigilance.** rust-analyzer runs architecture rules as `#[test]` tidy checks; Theia lints make the manifest graph the true graph (0 cycles across 91 packages); VS Code fails the build three independent ways. Zed's absence of enforcement is the cautionary contrast. Confidence: high.
4. **Decompose `AppState` into per-subsystem services behind narrow typed handles.** Zed's Global/Entity registry, Helix's main-loop boxed callbacks and ArcSwap config views, rust-analyzer's host/snapshot split, and ox's invertible event channel all avoid the cloned-into-every-handler god-struct. Confidence: high.
5. **Quarantine transport types from domain types - one crate owns the wire format.** rust-analyzer confines `lsp-types` to exactly 1 of 33 manifests; Helix splits `helix-lsp` from `helix-lsp-types`; VS Code derives wire types mechanically from interfaces. Confidence: high.
6. **Split each crate's modules by environment (pure core vs shell) and compile-check the split.** VS Code's environment-suffixed modules and Theia's lint-enforced runtime-folder layering force pure types downward. Confidence: medium.
7. **Encode crate convention in a scaffolding tool at the creation moment.** Zed's `script/new-crate` keeps 245 crates uniform; rust-analyzer's tidy checks enforce manifest shape. Confidence: medium.
8. **A feature-flagged headless backend decouples the view from the server build.** Helix's `TestBackend` swap runs the real application under integration tests; ox dogfoods built-in plugins through the same loader as user plugins. Confidence: medium.
9. **Phased contribution registration controls startup cost as subsystems multiply.** VS Code's `registerWorkbenchContribution2` lifecycle phases and Theia's root-pinned contribution providers matter once the IDE feature surface grows. Confidence: medium.

## Method

The subject (the `workshop` and `workshop-server` crates of the Runvil workspace) was profiled first through nine lenses, producing a fingerprint, seven named deficits, and five strengths. The field was surveyed from 20 candidates, 12 gathered, 10 verified against actual source manifests; Cursor and Kiro were confirmed closed-source and recorded as undiveable, with their open core (VS Code) and open clones standing in. Six references were dived in parallel at pinned commits, each idiom cited to file and line. Each cited idiom was dated by provenance examination - AI-marker scan since 2022, per-file history walks, and a pre-AI rewind comparison where markers appeared. Synthesis clustered idioms across briefs (multi-reference confirmation outranks single-source), mapped them onto named deficits, and ranked by payoff: deficit severity, convergence, adoption cost. All 75 citations were checked against the pinned clones: 59 passed as written, 16 were corrected, none were unverifiable.

## Baseline: where the subject stands

Workshop is two crates in a 37-crate Rust workspace: `workshop`, a ~3.5k-line Tauri desktop shell, and `workshop-server`, a ~18.2k-line axum HTTP server with 29 modules, plus a ~10k-line TypeScript SPA embedded into the server's binary. The Tauri shell spawns the server in-process on an OS-assigned loopback port and points its webview at it; the same code also builds standalone.

Strengths the field confirmed: a pure, fixture-pinned wire protocol (`protocol.rs` carries zero I/O and is asserted against JSON fixtures on both the Rust and TypeScript sides); written delivery semantics (durable/ephemeral classification, cursor-based repair, resend-on-reconnect); boundary error discipline (one `AppError`, central status mapping, no cross-wire `#[from]`); structural lifecycle (handle-based shutdown, cancel-as-stop-reason supervisors); and a one-way workspace graph that already holds.

Deficits the findings map to: (1) no registration mechanism - `app.rs` merges five routers by name and constructs nine subsystems explicitly; (2) the workspace's narrow-crate discipline stops at workshop-server's boundary - 29 modules in one crate; (3) `AppState` is a god-struct whose nine shared-mutable fields are cloned into every handler; (4) three hand-rolled copies of the same retained-bus pattern (~2k lines); (5) transport mixed into domain files - `workspace.rs` (1,273 lines) holds jail + errors + axum handlers, `gateway.rs` (1,236) holds client + SSE + socket; (6) the SPA is bundled by the server's build script and embedded into its binary; (7) the shell's `gateway/supervisor.rs` re-implements what `shared-sidecar` exists for.

## Detailed findings, ranked by payoff

### Finding 1: Subsystems self-register through a low-crate proxy registry; the composition root stops naming them

Every reference independently arrived at the same mechanism. Zed's is the most directly portable: a low crate owns a global proxy holding one `RwLock<Option<Arc<dyn Trait>>>` slot per subsystem; each subsystem self-registers at init, the host calls through the proxy while depending on no subsystem, and unregistered slots are graceful no-ops ([extension_host_proxy.rs](https://github.com/zed-industries/zed/blob/a2651e3b5639d7f050d02ca8a863ca7d078a7dad/crates/extension/src/extension_host_proxy.rs); registration at [language_extension.rs:18-31](https://github.com/zed-industries/zed/blob/a2651e3b5639d7f050d02ca8a863ca7d078a7dad/crates/language_extension/src/language_extension.rs#L18-L31), [theme_extension.rs:16](https://github.com/zed-industries/zed/blob/a2651e3b5639d7f050d02ca8a863ca7d078a7dad/crates/theme_extension/src/theme_extension.rs#L16)). VS Code's service identifiers double as type-level keys and constructor-parameter decorators, with implementations self-registering via `registerSingleton` in their own module ([instantiation.ts:109-126](https://github.com/microsoft/vscode/blob/3addbda66f9e80c3ed1b943822ab823bb6747b02/src/vs/platform/instantiation/common/instantiation.ts#L109-L126), [extensions.ts:24-33](https://github.com/microsoft/vscode/blob/3addbda66f9e80c3ed1b943822ab823bb6747b02/src/vs/platform/instantiation/common/extensions.ts#L24-L33)). Theia binds services to contribution symbols in per-package `ContainerModule`s and collects them through `ContributionProvider<T>` ([frontend-application-module.ts:155](https://github.com/eclipse-theia/theia/blob/69805e3299deb477431e6d1e527bd7ebada5726a/packages/core/src/browser/frontend-application-module.ts#L155), [contribution-provider.ts:20-64](https://github.com/eclipse-theia/theia/blob/69805e3299deb477431e6d1e527bd7ebada5726a/packages/core/src/common/contribution-provider.ts#L20-L64)). rust-analyzer uses one alphabetical function-pointer table ([ide-assists/src/lib.rs:242-248](https://github.com/rust-lang/rust-analyzer/blob/6aeeb8cf02741e5da07a1615a05faa506cecb21a/crates/ide-assists/src/lib.rs#L242-L248)), Helix uses `register_hook!` macros under one `handlers::setup` root ([helix-event/src/lib.rs:110-205](https://github.com/helix-editor/helix/blob/079a789e8cb08ead67f19e1971a1b7438b37354b/helix-event/src/lib.rs#L110-L205), [handlers.rs:30-68](https://github.com/helix-editor/helix/blob/079a789e8cb08ead67f19e1971a1b7438b37354b/helix-term/src/handlers.rs#L30-L68)), and ox merges plugin convention tables after load ([run.lua:5-20](https://github.com/curlpipe/ox/blob/6cb11e7dbb0817d3590e4db8098b4b42c366b278/src/plugin/run.lua#L5-L20)).

This replaces the hand-wiring in `app.rs`, where `router()` merges five routers by name and `AppState::new` constructs nine subsystems explicitly. The fix: a bottom `workshop-registry` crate owns one proxy slot per subsystem (routes, state handle, shutdown); each subsystem crate registers itself in an `init` the shell calls; adding a subsystem becomes a one-line change in exactly one place. Confidence: high - six of six references converge on the mechanism.

### Finding 2: Split the monolith into one-way layer crates with written per-crate invariants

rust-analyzer's parser -> syntax -> base-db -> hir -> ide-db -> ide layering carries a written invariant list per boundary ([architecture.md:50-56](https://github.com/rust-lang/rust-analyzer/blob/6aeeb8cf02741e5da07a1615a05faa506cecb21a/docs/book/src/contributing/architecture.md#L50-L56), [Cargo.toml:50-86](https://github.com/rust-lang/rust-analyzer/blob/6aeeb8cf02741e5da07a1615a05faa506cecb21a/Cargo.toml#L50-L86)). Helix publishes the crate table as documentation and lets Cargo make cycles unrepresentable ([architecture.md:3-13](https://github.com/helix-editor/helix/blob/079a789e8cb08ead67f19e1971a1b7438b37354b/docs/architecture.md#L3-L13)). Zed splits a narrow 8-file `extension` interface crate from the deep `extension_host` implementation so consumers depend on the narrow crate alone ([extension.rs](https://github.com/zed-industries/zed/blob/a2651e3b5639d7f050d02ca8a863ca7d078a7dad/crates/extension/src/extension.rs), [extension_host.rs](https://github.com/zed-industries/zed/blob/a2651e3b5639d7f050d02ca8a863ca7d078a7dad/crates/extension_host/src/extension_host.rs)). ox extracts its whole document backend into kaolinite behind ~10 public types ([kaolinite/src/lib.rs:29-36](https://github.com/curlpipe/ox/blob/6cb11e7dbb0817d3590e4db8098b4b42c366b278/kaolinite/src/lib.rs#L29-L36)).

This addresses the monolithic server crate: 29 modules and 18k lines where the workspace's narrow-crate discipline stops. The fix: extract leaf-first - protocol/vocabulary, then domain services (gateway lifecycle, progress, catalog), then features (sessions, workspace, menu) - with `workshop-server` slimming to the composition root and HTTP shell, each new crate carrying a written invariant list. Confidence: high - four references, and the subject's own workspace already demonstrates the discipline outside this crate.

### Finding 3: Enforce the graph mechanically - invariants as tests, not reviewer vigilance

rust-analyzer runs architecture rules as `#[test]` tidy checks: module doc headers, Cargo.toml dependency shape, license allowlist, paired coverage marks ([tidy.rs:14-20](https://github.com/rust-lang/rust-analyzer/blob/6aeeb8cf02741e5da07a1615a05faa506cecb21a/xtask/src/tidy.rs#L14-L20), [83-132](https://github.com/rust-lang/rust-analyzer/blob/6aeeb8cf02741e5da07a1615a05faa506cecb21a/xtask/src/tidy.rs#L83-L132), [133-192](https://github.com/rust-lang/rust-analyzer/blob/6aeeb8cf02741e5da07a1615a05faa506cecb21a/xtask/src/tidy.rs#L133-L192), [315-365](https://github.com/rust-lang/rust-analyzer/blob/6aeeb8cf02741e5da07a1615a05faa506cecb21a/xtask/src/tidy.rs#L315-L365)). Theia's custom lint rules make the manifest graph the true graph - no deep `/src/` imports, every cross-package import a declared dependency, runtime-folder layering enforced - with 0 cycles verified across 91 packages ([no-src-import.js:40-49](https://github.com/eclipse-theia/theia/blob/69805e3299deb477431e6d1e527bd7ebada5726a/dev-packages/private-eslint-plugin/rules/no-src-import.js#L40-L49), [runtime-import-check.js:57-64](https://github.com/eclipse-theia/theia/blob/69805e3299deb477431e6d1e527bd7ebada5726a/dev-packages/private-eslint-plugin/rules/runtime-import-check.js#L57-L64), [errors.eslintrc.json:147-149](https://github.com/eclipse-theia/theia/blob/69805e3299deb477431e6d1e527bd7ebada5726a/configs/errors.eslintrc.json#L147-L149)). VS Code fails the build three independent ways: per-layer tsconfigs, `layersChecker`, and `checkCyclicDependencies` on the compiled output ([tsconfig.browser.json:14-24](https://github.com/microsoft/vscode/blob/3addbda66f9e80c3ed1b943822ab823bb6747b02/build/checker/tsconfig.browser.json#L14-L24), [layersTypeCheck.ts:11-16](https://github.com/microsoft/vscode/blob/3addbda66f9e80c3ed1b943822ab823bb6747b02/build/checker/layersTypeCheck.ts#L11-L16)). The cautionary contrast is Zed, which has no automated enforcement - [script/crate-dep-graph](https://github.com/zed-industries/zed/blob/a2651e3b5639d7f050d02ca8a863ca7d078a7dad/script/crate-dep-graph) renders an SVG only, and layering holds by review.

The subject's one-way graph currently holds by Cargo acyclicity alone, and its module-level conventions are unenforced. The fix: an `xtask` member running tidy-style architecture tests - allowed-dependency tables per crate, forbidden module pairs, file-size ceilings - as `#[test]`s that fail the build. Confidence: high - three references enforce, and the one that doesn't is the field's most famous god-file owner.

### Finding 4: Decompose the god-struct into per-subsystem services behind narrow typed handles

Zed's gpui model installs singletons via `Global` and shares state as `Entity<T>` handles - no god-struct aggregates subsystems ([extension_host_proxy.rs:13-48](https://github.com/zed-industries/zed/blob/a2651e3b5639d7f050d02ca8a863ca7d078a7dad/crates/extension/src/extension_host_proxy.rs#L13-L48)). Helix mutates its single state root only on the main loop via boxed `FnOnce(&mut Editor)` callbacks returned through a channel - no locks in the state path ([job.rs:11-40](https://github.com/helix-editor/helix/blob/079a789e8cb08ead67f19e1971a1b7438b37354b/helix-term/src/job.rs#L11-L40), [104-128](https://github.com/helix-editor/helix/blob/079a789e8cb08ead67f19e1971a1b7438b37354b/helix-term/src/job.rs#L104-L128)) - and hands subsystems type-erased read-only config views over ArcSwap ([application.rs:122-130](https://github.com/helix-editor/helix/blob/079a789e8cb08ead67f19e1971a1b7438b37354b/helix-term/src/application.rs#L122-L130), [editor.rs:1315](https://github.com/helix-editor/helix/blob/079a789e8cb08ead67f19e1971a1b7438b37354b/helix-view/src/editor.rs#L1315)). rust-analyzer splits mutable `AnalysisHost` from immutable `Analysis` snapshots with cancel-by-revision, catching panic once at the crate edge ([ide/src/lib.rs:154-243](https://github.com/rust-lang/rust-analyzer/blob/6aeeb8cf02741e5da07a1615a05faa506cecb21a/crates/ide/src/lib.rs#L154-L243)). ox funnels every mutation through one invertible `Event` enum whose `reverse()` yields undo ([event.rs:15-37](https://github.com/curlpipe/ox/blob/6cb11e7dbb0817d3590e4db8098b4b42c366b278/kaolinite/src/event.rs#L15-L37)).

This addresses `AppState`: nine shared-mutable fields cloned into every handler, with subsystems coupling through it (`SessionHost` carries five buses). The fix: each subsystem crate owns its state type behind a narrow handle trait; handlers receive only the handles their route needs; `AppState` shrinks to the registry of handles. Confidence: high - four references, and the subject's fields already have single owners, so the decomposition is latent.

### Finding 5: Quarantine transport types from domain types - one crate owns the wire format

rust-analyzer confines `lsp-types` to exactly 1 of 33 crate manifests, keeps Serialize derives off domain types, and hand-writes the conversion layer ([to_proto.rs](https://github.com/rust-lang/rust-analyzer/blob/6aeeb8cf02741e5da07a1615a05faa506cecb21a/crates/rust-analyzer/src/lsp/to_proto.rs), [architecture.md:232-235](https://github.com/rust-lang/rust-analyzer/blob/6aeeb8cf02741e5da07a1615a05faa506cecb21a/docs/book/src/contributing/architecture.md#L232-L235)). Helix quarantines LSP as a crate pair - `helix-lsp` owns transport, `helix-lsp-types` is pure types, the editor sees only a Registry and `Call` events ([helix-lsp/src/lib.rs:10](https://github.com/helix-editor/helix/blob/079a789e8cb08ead67f19e1971a1b7438b37354b/helix-lsp/src/lib.rs#L10), [editor.rs:1354](https://github.com/helix-editor/helix/blob/079a789e8cb08ead67f19e1971a1b7438b37354b/helix-view/src/editor.rs#L1354)). VS Code derives wire types mechanically from interfaces via the `Dto<T>` mapped type ([proxyIdentifier.ts:56-72](https://github.com/microsoft/vscode/blob/3addbda66f9e80c3ed1b943822ab823bb6747b02/src/vs/workbench/services/extensions/common/proxyIdentifier.ts#L56-L72)).

This addresses transport mixed into domain files: `workspace.rs` holds jail + errors + axum handlers in 1,273 lines; `gateway.rs` holds client + SSE + socket in 1,236. The subject already proves the pattern with `protocol.rs` - the fix is extending that purity outward: axum handlers and SSE/websocket plumbing move to the shell crate; domain crates expose pure types and events. Confidence: high - three references, and the subject's own protocol module is the working exemplar.

### Finding 6: Split each crate's modules by environment (pure core vs shell) and compile-check the split

VS Code suffixes every module with its environment (`common|browser|node|electron-main|electron-utility`) and compiles each layer with a tsconfig that only includes legal subfolders - cross-layer reach is a compile error ([tsconfig.browser.json:14-24](https://github.com/microsoft/vscode/blob/3addbda66f9e80c3ed1b943822ab823bb6747b02/build/checker/tsconfig.browser.json#L14-L24), [layersTypeCheck.ts:11-16](https://github.com/microsoft/vscode/blob/3addbda66f9e80c3ed1b943822ab823bb6747b02/build/checker/layersTypeCheck.ts#L11-L16)). Theia enforces the same inside every package: `common` imports nothing runtime-specific, `browser`/`node` may import `common`, and the custom `runtime-import-check` lint rule errors on violations ([runtime-import-check.js:57-64](https://github.com/eclipse-theia/theia/blob/69805e3299deb477431e6d1e527bd7ebada5726a/dev-packages/private-eslint-plugin/rules/runtime-import-check.js#L57-L64), [errors.eslintrc.json:147](https://github.com/eclipse-theia/theia/blob/69805e3299deb477431e6d1e527bd7ebada5726a/configs/errors.eslintrc.json#L147)).

The Rust analog for each new workshop crate: a pure core module tree plus a thin shell module, with a tidy-style test (Finding 3) rejecting forbidden module pairs. Confidence: medium - two references converge, but the mechanism is TypeScript-specific and needs translation to Cargo idioms.

### Finding 7: A crate scaffolding tool encodes the convention at the creation moment

Zed's `script/new-crate` generates a workspace-lints-inheriting manifest, the `[lib] path` layout, and a symlinked license, and refuses AGPL - 245 crates stay uniform because conforming is the easiest path ([script/new-crate](https://github.com/zed-industries/zed/blob/a2651e3b5639d7f050d02ca8a863ca7d078a7dad/script/new-crate)). rust-analyzer's tidy checks enforce Cargo.toml dependency shape across the workspace as tests ([tidy.rs:83-132](https://github.com/rust-lang/rust-analyzer/blob/6aeeb8cf02741e5da07a1615a05faa506cecb21a/xtask/src/tidy.rs#L83-L132)).

As the workshop crate family grows from 2 toward IDE scale, an `xtask` generator producing new crates with inherited lints, correct layer dependencies, and the standard layout keeps the graph uniform by default. Confidence: medium - two references; payoff scales with crate count.

### Finding 8: A feature-flagged headless backend decouples the view from the server build

Helix's `integration` feature swaps `TerminalBackend` for `TestBackend` at the type level so the real `Application` runs under key-sequence integration tests ([application.rs:52-60](https://github.com/helix-editor/helix/blob/079a789e8cb08ead67f19e1971a1b7438b37354b/helix-term/src/application.rs#L52-L60), [tests/integration.rs:13](https://github.com/helix-editor/helix/blob/079a789e8cb08ead67f19e1971a1b7438b37354b/helix-term/tests/integration.rs#L13)). ox ships built-in plugins through the same loader as user plugins via `include_str!`, dogfooding the plugin API ([config/mod.rs:35-38](https://github.com/curlpipe/ox/blob/6cb11e7dbb0817d3590e4db8098b4b42c366b278/src/config/mod.rs#L35-L38), [216-224](https://github.com/curlpipe/ox/blob/6cb11e7dbb0817d3590e4db8098b4b42c366b278/src/config/mod.rs#L216-L224)).

This addresses the view coupled to the server build: the 10k-line SPA lives under the server crate, bundled by its build script and embedded into its binary. The fix: the UI bundle becomes its own deliverable consumed through a narrow asset-serving interface, and a headless feature lets the real server run under end-to-end tests without the webview. Confidence: medium - two references; the subject's debug/release asset split is already half the mechanism.

### Finding 9: Phased contribution registration controls startup cost as subsystems multiply

VS Code's `registerWorkbenchContribution2` ties each contribution to a lifecycle phase (`BlockStartup..Eventually`) or lazy/editor-scoped instantiation ([contributions.ts:30-62](https://github.com/microsoft/vscode/blob/3addbda66f9e80c3ed1b943822ab823bb6747b02/src/vs/workbench/common/contributions.ts#L30-L62)). Theia pins contribution collection to the root container via `bindRootContributionProvider` ([contribution-provider.ts:20-64](https://github.com/eclipse-theia/theia/blob/69805e3299deb477431e6d1e527bd7ebada5726a/packages/core/src/common/contribution-provider.ts#L20-L64), [119-130](https://github.com/eclipse-theia/theia/blob/69805e3299deb477431e6d1e527bd7ebada5726a/packages/core/src/common/contribution-provider.ts#L119-L130)).

Once Finding 1 lands and the subsystem count grows toward IDE feature surface, registration needs a phase dimension so startup cost stays flat. Confidence: medium - two references; premature before the registry exists.

## Provenance

Five cited idioms carry `explicit AI marker`; every rewind showed the mechanism human-originated and intact. Zed's extension-API files received Claude-co-authored commits in 2026, but the versioned WIT dispatch, the `zed:api-version` custom-section parser, and the narrow/deep crate split were all fully present at their pre-AI commits - the AI commits extended the newest snapshot and adjusted scheduler plumbing only. VS Code's `layersChecker.ts` has three AI commits from 2026-07, but the RULES mechanism has been human-maintained since 2020 and stands intact at its rewind; its sibling `layersTypeCheck.ts` and `checkCyclicDependencies.ts` are AI-originated (2026) with no pre-AI form - notable as the newest layer of a three-deep enforcement stack. VS Code's side-effect-import composition root was fully formed at its rewind (202 bare imports, 2019 origin). The one adverse finding is not an idiom but a mess: VS Code's `chatInputPart.ts` grew from 1,661 to 4,731 lines with 110 of 947 commits AI-marked - the megafile mess there is substantially AI-era growth, while the older megafiles (`extHost.protocol.ts`, `editorOptions.ts`) predate AI and merely grew during it.

## Where the subject already matches or beats the references

- Fixture-pinned pure protocol beats ox's stringly-typed Lua bridge, which has no schema or fixture and drifts at runtime; it matches VS Code's `Dto`-derived wire types in intent at smaller scale.
- Structural lifecycle (handle-based shutdown that wins selects, cancel-as-stop-reason) matches VS Code's disposal tree, which needs three custom eslint rules to hold; Rust's `Drop` makes the same discipline structural.
- Boundary error discipline (one `AppError`, central status mapping, no cross-wire `#[from]`, debug-only detail leakage) exceeds anything the dive briefs surfaced in the six references.
- The one-way workspace graph already holds - only `workshop` depends on `workshop-server`, nothing depends back up the stack - matching Helix and rust-analyzer discipline at smaller scale.
- Written delivery semantics (durable/ephemeral classification, cursor-based repair, resend-on-reconnect) have no comparable documented mechanism in any dive brief.

## Messes we should explicitly not copy

- Zed: `crates/workspace/src/workspace.rs` is 20,047 lines, `pane.rs` 9,665, `crates/project/src/lsp_store.rs` 690 KB - excellent crate granularity with a god-file at the exact center.
- Zed: no automated dependency-graph enforcement; `script/crate-dep-graph` renders an SVG only.
- Zed: style clippy lints globally allowed with an explicit velocity rationale.
- VS Code: `extHost.protocol.ts` carries every MainThread/ExtHost interface pair in ~4,200 lines - a reverse-dependency magnet that grew ~50% in the AI era.
- VS Code: `editorOptions.ts` (255 KB) and `chatInputPart.ts` (251 KB) megafiles persist even there.

## Recommended execution order

1. **Stand up enforcement and scaffolding first** (Findings 3, 7): an `xtask` member with tidy-style architecture tests (allowed-dependency tables, forbidden module pairs, file-size ceilings) and a new-crate generator. Cheap, and it guards every later step.
2. **Build the registry** (Finding 1): a bottom `workshop-registry` crate with one proxy slot per subsystem; subsystems self-register; `app.rs` stops naming them. This is the keystone - it makes the split possible without cycles.
3. **Decompose `AppState`** (Finding 4): each subsystem owns its state behind a narrow handle; handlers take only the handles they need. Same files as step 2's callers; merge the passes.
4. **Extract crates leaf-first** (Findings 2, 5, 6): protocol/vocabulary, then domain services (gateway lifecycle, progress, catalog), then features (sessions, workspace, menu); transport code moves shell-ward as each crate forms; each crate gets a written invariant list that the step-1 tests enforce.
5. **Decouple the view** (Finding 8): the UI bundle becomes its own deliverable behind a narrow asset interface; a headless feature enables end-to-end tests.
6. **Add phased registration** (Finding 9) once subsystem count justifies it.
7. **Local refactors with no field idiom needed**: collapse the three hand-rolled retained buses into one generic abstraction (deficit 4); delete the shell's duplicated gateway supervisor in favor of `shared-sidecar` (deficit 7).

## Refactor notes

Findings 1, 3, and 7 are pure structure - no behavior changes. Findings 2, 4, 5, and 6 move code and reshape `pub` surfaces but must not change the wire protocol or delivery semantics; Finding 8 changes the build pipeline; Finding 9 changes startup timing. The test suite is the invariant and moves last in each step: `protocol.rs`'s fixtures and the session delivery tests pin the behavior that the restructure must preserve. Do-not-touch boundaries: the wire format in `protocol.rs` and its JSON fixtures, and the public APIs of the `runvil-*` and `shared-*` crates. Each step verifies with `cargo clippy --all-targets --all-features -- -D warnings` and `cargo test --locked --workspace` and commits independently. Stop condition: two consecutive failures on one step stops the run for a re-plan.
