# Workshop: How to Link to Any Artifact

Report type: evaluation / review. It judges the Workshop (Tauri shell, axum server, TypeScript SPA) against 6 popular codebases sharing the technique of custom URL schemes and internal artifact links, and prescribes idioms to adopt, in payoff order.

## Executive summary

The Workshop has no way to name anything it owns: a panel id is a private `type:param` string, a rendered link navigates the webview away, a second launch throws its arguments on the floor, and no route serves an object by identity. Six references that solved this, from VS Code's 2015 `URI` to Zotero's 2007 protocol handler, converge on one shape: a single address value type with one parser, an opener registry that hands an address to the view that claims it, a delegated click handler that never lets an anchor navigate, a label service so no raw id is ever displayed, a ready-gated intake for links arriving from outside, and id-keyed routes for content. The Workshop already has the two things the references struggled with, a type-keyed slot registry with lifetime guards and a fixture-pinned protocol, so the top finding pays by giving those a grammar to carry. Where it wins: nothing in the field pins two parsers to one fixture the way the Workshop's protocol already does.

### Key findings

1. **One address value type, one parser, one serializer, pinned by a round-trip fixture, from VS Code and Trilium with Zotero and Zed corroborating.** Parse failure is a value, never an exception at the click boundary; the list of kinds lives in one registry. Confidence: high.
2. **An opener registry with priority or order, disposable registration, one entry function, and a handler kind that says navigate-versus-content, from Theia and Zotero.** Replaces 11 direct `openInZone` call sites. Confidence: high.
3. **Neuter every rendered anchor and route one delegated click through the opener, from VS Code and Trilium.** `href` becomes `data-href` at render; internal-versus-external is decided by the parser; a modifier table picks same pane, new tab, or new split. Confidence: high.
4. **Deep-link intake as one channel with a ready-gated queue and a URL firewall, from VS Code, Theia, and Element.** Every inbound source enters the same intake; the URL is parsed and rebuilt, never forwarded; the queue holds until the window is ready. Confidence: high on the shape, medium on the Tauri specifics.
5. **Display names from a kind-keyed label service with priority, a degrade chain, and a change event, from Theia and VS Code.** Resolved name, then noun plus id, then a generic; a change event re-labels tabs. Confidence: high.
6. **Virtual resources keyed by id with a presentational filename tail, served by providers that refuse duplicate registration, from Trilium and VS Code.** The last segment names the download and the language, never the lookup; `no-store` on every response. Confidence: high on routes, medium on streaming bodies.
7. **Panel identity derived from the address by one function, fragments stripped, the key round-tripping through layout persistence, from Theia.** `panelIdFor` becomes a function of the address for every artifact-backed panel. Confidence: medium.

## Method

The subject was profiled first through nine lenses (module decomposition, state ownership, boundaries, error shape, resource lifecycle, testing, comment policy, build and delivery, messes), producing a fingerprint with six focus deficits and five strengths. The field was surveyed stack-agnostically for the technique, seventeen candidates were verified against source, and six were shortlisted. Six parallel dives read each reference at a pinned commit through the host's raw content endpoints rather than local clones, which the run environment could not create; line numbers therefore come from fetched content. Provenance examiners walked every cited file's commit history through the host's commits API, which does not follow renames, so histories truncated at tree moves are tagged unknown rather than guessed; where an AI-marked commit touched a cited file, the file was read at its last pre-AI commit and compared. Synthesis clustered idioms by convergence and mapped each onto a named deficit. A citation check re-fetched 97 citations at the pinned commits: 84 passed as written, 13 were corrected to adjacent ranges in the same files with the mechanism present, and none were unverifiable. Fourteen supporting file-level citations without line numbers (bundle manifests, desktop entries, installer scripts, builder configs) were not independently re-fetched under the check's budget and are marked as such where cited.

## Baseline: where the subject stands

The Workshop is a Tauri 2 binary hosting an axum server in-process on an OS-assigned loopback port, with a code-split TypeScript SPA embedded by rust-embed and served to one webview under an exact-origin capability built at runtime. Roughly a third of its source is TypeScript, a third tests, a third Rust split across the server, the shell, a protocol crate, and a registry crate.

Strengths the findings build on: a type-keyed slot registry with RAII registration guards and boot-time `require`; a twin-pinned protocol whose Rust and TypeScript sides share one JSON fixture and classify every frame as durable or ephemeral; a runtime exact-origin capability with a tested navigation policy; a metadata-eager, code-lazy panel registry with reversible ids; and a validated HTTP boundary with code-matched errors.

Deficits the findings map to: (1) no internal URI grammar, identity is the dock-private `panelIdFor` string; (2) no opener or resolver registry, eleven call sites open panels directly; (3) rendered markdown emits plain anchors and nothing intercepts clicks, so a same-origin link navigates the SPA away; (4) no OS deep link, the single-instance callback discards its arguments; (5) no virtual resources over HTTP, every route addresses a bundle asset or a raw OS path; (6) display names know only a file's basename or a static type title.

## Detailed findings, ranked by payoff

### Finding 1: One address value type, one parser, one serializer, pinned by a round-trip fixture
