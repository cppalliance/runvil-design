# Runvil Gateway: How to Structure an axum Server

Report type: evaluation / review. It judges the Runvil gateway app crate against 5 popular codebases sharing the Rust axum multi-tier API server technique, and prescribes idioms to adopt, in payoff order.

## Executive summary

The gateway's route table is a 120-line function that knows every tier, every feature gate, and every handler by name, and three of the five references show the same surface built the other way round. The subject is weaker on layout: the auth tier is decided by row position in `build_router`, the `admin/` directory holds 5 of 19 admin modules, and the same two lines of glue (rejection mapping, blocking-task join mapping) are hand-copied at 7 and 11 sites respectively. It already wins on the HTTP edge: one `AuthedCaller` extractor, one flat `GatewayError` with a table-driven classifier, a loopback wall no reference has, strict lints, and in-process race tests. The top finding moves each route area's mounts into a tier-named `routes()` constructor in its own module and applies the wall at the merge site, which makes the tier readable from the file path and turns `build_router` into a dozen merges.

### Key findings

1. **Tier-named per-area router constructors merged at the root, with the wall applied at the merge site (Windmill, Svix, llm-gateway-rs; SGLang corroborates).** Each area module's only public route item becomes `pub(crate) fn routes() -> Router<AppState>`; walled areas live under one directory and are merged through the loopback layer once. Confidence: high.
2. **`WireQuery` and `WirePath` wrapper extractors with `Rejection = GatewayError` (Svix; mistral.rs).** The seven hand-rolled `map_err(... rejection.body_text())` lines and their copied comment become two ten-line impls beside the existing `WireJson`. Confidence: high.
3. **One `blocking()` helper owning `spawn_blocking` and the join mapping (Windmill; Svix; mistral.rs).** Eleven call sites choosing among six `GatewayError` variants collapse to one function and one variant. Confidence: high.
4. **A typed loopback-tier extractor beside `AuthedCaller` (Svix).** A handler that must be loopback-only says so in its signature; the `route_layer` wall stays as defense in depth. Confidence: medium.
5. **Typed response structs for the admin surface (SGLang, llm-gateway-rs, Svix).** `serde_json::json!` literals pinned only by integration tests become `Serialize` structs the config UI shape is checked against. Confidence: medium.
6. **A typed route registry with a tier kind, pinned by a test, replacing the 80-line doc paragraph (mistral.rs).** Each area declares `const` route infos; one test asserts every mounted route is registered under the tier its module claims. Confidence: medium.
7. **Thin handlers over transport-free command functions; split `config_apply.rs` (SGLang, llm-gateway-rs).** The apply and revert routes become adapters over a command module that knows nothing of axum. Confidence: medium.
8. **A builder for `AppState` assembly (SGLang; mistral.rs).** The nine-parameter `from_parts` behind a `too_many_arguments` waiver becomes a builder tests can partially override. Confidence: low.

## Method

The subject was profiled first through nine lenses (module decomposition, state ownership, boundaries, error shape, resource lifecycle, testing, comment policy, build and delivery, messes), yielding eight named deficits and five strengths. The field was surveyed with 17 candidates, 13 verified against source manifests and files, and 5 shortlisted by technique match. Five parallel dives cloned each reference at a pinned commit and applied the same nine lenses. Each cited idiom was then dated: commit history was scanned for AI markers, and where a cited file carried one, the mechanism at HEAD was compared against its last pre-marker form. Findings were synthesized by convergence and deficit mapping, then every reference citation was checked against the pinned clones: 44 of 49 passed as written and 5 were corrected; none were unverifiable.

## Baseline: where the subject stands

The subject is a ~23,000-line Rust crate (plus ~9,600 lines of integration tests) built on axum and tokio: a tray-resident binary serving an OpenAI-shaped inference API, a loopback-walled admin API, and an embedded config SPA, with four default-on additive features (`local`, `web-search`, `config-ui`, `stt`). Shared state is a cloned `AppState` holding `Arc<RwLock<LiveState>>` behind accessors plus process-lifetime singletons and an apply mutex. Errors are one flat `GatewayError` with a table-driven `classify()` to status, type, and code. Auth is an `AuthedCaller` extractor that runs bearer, cookie, and loopback-trust rules before body extraction.

Strengths the field confirms: the `AuthedCaller` extractor, the single error type and classifier, the typed `AppState` over request extensions, the in-process router tests with forged peers and the `PhasePark` race rendezvous, the denied `unwrap`/`expect` lint set, and a loopback wall none of the five references has.

Deficits the findings map to: (1) eleven `spawn_blocking` sites hand-map `JoinError` to six variants; (2) extractor rejections are mapped two ways, `WireJson` and a copied `map_err` line at seven sites; (3) the auth tier is decided only by row position in the route table; (4) the stated `admin/` directory convention is honored by 5 of 19 admin route modules; (5) four files exceed 1,000 lines with mixed roles (`runner.rs`, `commands.rs`, `dialect.rs`, `config_apply.rs`); (6) admin responses are untyped `json!` literals; (7) three test-placement conventions coexist; (8) the crate-root doc is an 80-line paragraph duplicating the route table beneath it.

## Detailed findings, ranked by payoff

### Finding 1: Tier-named per-area router constructors, merged at the root, wall applied at the merge site

Three of five references decentralize route registration and make the auth tier readable from the constructor name or the file path. Windmill gives every area module tier-named constructors, `workspaced_service()` and `global_service()` ([groups.rs L34-L58](https://github.com/windmill-labs/windmill/blob/6186a0645d3f3e92e06b666a6b5774b8af2b488f/backend/windmill-api-groups/src/groups.rs#L34-L58)), and its mount tree places every authed mount above a single `route_layer(from_extractor::<ApiAuthed>())` line and every unauthed mount below it ([lib.rs L785-L799](https://github.com/windmill-labs/windmill/blob/6186a0645d3f3e92e06b666a6b5774b8af2b488f/backend/windmill-api/src/lib.rs#L785-L799), [L821-L822](https://github.com/windmill-labs/windmill/blob/6186a0645d3f3e92e06b666a6b5774b8af2b488f/backend/windmill-api/src/lib.rs#L821-L822), [L863-L886](https://github.com/windmill-labs/windmill/blob/6186a0645d3f3e92e06b666a6b5774b8af2b488f/backend/windmill-api/src/lib.rs#L863-L886)). Svix merges one `router()` per resource at the version root and applies state once ([v1/mod.rs L16-L25](https://github.com/svix/svix-webhooks/blob/924f07eae5b86f025fbfe5da07a6685148e89798/server/svix-server/src/v1/mod.rs#L16-L25), [application.rs L463-L480](https://github.com/svix/svix-webhooks/blob/924f07eae5b86f025fbfe5da07a6685148e89798/server/svix-server/src/v1/endpoints/application.rs#L463-L480), [lib.rs L209-L216](https://github.com/svix/svix-webhooks/blob/924f07eae5b86f025fbfe5da07a6685148e89798/server/svix-server/src/lib.rs#L209-L216)). llm-gateway-rs makes `pub fn router()` each area's only public route item and applies that tier's auth layer at the nest site ([admin.rs L308-L324](https://github.com/poly-workshop/llm-gateway-rs/blob/a580c58d3ae9af06b90632b25b03c6223e74f01d/src/routes/admin.rs#L308-L324), [proxy.rs L486-L488](https://github.com/poly-workshop/llm-gateway-rs/blob/a580c58d3ae9af06b90632b25b03c6223e74f01d/src/routes/proxy.rs#L486-L488), [main.rs L90-L132](https://github.com/poly-workshop/llm-gateway-rs/blob/a580c58d3ae9af06b90632b25b03c6223e74f01d/src/main.rs#L90-L132)). SGLang centralizes but still names the tier as a function, `apply_control_plane_auth`, applied to both control-plane sub-routers ([server.rs L641-L655](https://github.com/sgl-project/sglang/blob/745de73ba3c136b6f99b7a3e2177ed1a8eef4a56/sgl-model-gateway/src/server.rs#L641-L655)). Windmill also degrades feature-gated mounts to `Router::new()` so the URL space is identical in every build ([lib.rs L696-L716](https://github.com/windmill-labs/windmill/blob/6186a0645d3f3e92e06b666a6b5774b8af2b488f/backend/windmill-api/src/lib.rs#L696-L716)).

In the subject this replaces `build_router` in `lib.rs` (lines 507-631, under a `too_many_lines` waiver), the module list at the crate root, and the flat placement of `system`, `hf`, `reveal`, `cloud_models`, `env_file`, `config_write`, `config_pending`, `config_apply`, `model_info`, `orphans`, `chat_templates`, `shutdown`, and `handoff` beside `admin/`.

The fix: give each area module `pub(crate) fn routes() -> Router<AppState>`; move the walled admin modules under one directory (for example `admin/walled/`) and the open ones under another, so the module path states the tier; `build_router` becomes `Router::new().merge(relay::routes()).merge(...)` for the open tier and `.merge(admin::walled::routes().route_layer(require_loopback))` once for the walled tier, then the existing STT merge, SPA nest, and host wall. Confidence: high - three references converge and two sibling crates in the same workspace already expose `routes()` this way.

### Finding 2: `WireQuery` and `WirePath` wrapper extractors with `Rejection = GatewayError`

Svix implements `ValidatedQuery<T>` and `ValidatedJson<T>` as extractors whose `Rejection = Error`, so a bad query or body lands in the documented envelope with no per-handler code; oversize bodies map to 413 and `serde_path_to_error` supplies the failing field path in the 422 ([utils/mod.rs L513-L588](https://github.com/svix/svix-webhooks/blob/924f07eae5b86f025fbfe5da07a6685148e89798/server/svix-server/src/v1/utils/mod.rs#L513-L588)); handlers simply consume them ([admin.rs L12-L15](https://github.com/svix/svix-webhooks/blob/924f07eae5b86f025fbfe5da07a6685148e89798/server/svix-server/src/v1/endpoints/admin.rs#L12-L15)). mistral.rs takes the half-step: one shared `ApiError::from_json_rejection` with per-status codes ([handler_core.rs L168-L182](https://github.com/EricLBuehler/mistral.rs/blob/d5ae0f18f2170f10d30880cb7d21fb0880410e7b/mistralrs-server-core/src/handler_core.rs#L168-L182), called at [handlers.rs L319-L325](https://github.com/EricLBuehler/mistral.rs/blob/d5ae0f18f2170f10d30880cb7d21fb0880410e7b/mistralrs-server-core/src/handlers.rs#L319-L325)), yet still defers `Result<Json<T>, JsonRejection>` by hand at 23 sites and grew a second copy of the mapper in `lora_adapters.rs` ([L705-L715](https://github.com/EricLBuehler/mistral.rs/blob/d5ae0f18f2170f10d30880cb7d21fb0880410e7b/mistralrs-server-core/src/lora_adapters.rs#L705-L715)). That is the subject's exact trajectory if it stops at a shared function; the wrapper extractor is what removes the per-site line.

In the subject this replaces the deferred `Result<Query<_>, QueryRejection>` and `Result<Path<_>, PathRejection>` parameters and their identical `map_err(|rejection| GatewayError::MalformedRequest(rejection.body_text()))` lines in `config_write.rs`, `env_file.rs` (twice), `reveal.rs`, `model_info.rs`, and `hf.rs` (twice). `WireJson` in `error.rs` already exists; the three `Result<Json<_>, JsonRejection>` sites can switch to it as-is since it runs after `AuthedCaller` when listed after it.

The fix: add `WireQuery<T>` and `WirePath<T>` beside `WireJson` with the same `FromRequestParts` shape, and delete the seven copies. Confidence: high - mechanical, and the subject already owns the pattern for one extractor.

### Finding 3: One `blocking()` helper owning `spawn_blocking` and the join mapping

Three references reach one conclusion by three routes: the join failure of a blocking task is not a domain error and should be mapped in exactly one place. Windmill's npm proxy has `blocking(work) -> Result<T>` wrapping `spawn_blocking` and mapping the join once ([lib.rs L1034-L1040](https://github.com/windmill-labs/windmill/blob/6186a0645d3f3e92e06b666a6b5774b8af2b488f/backend/windmill-api-npm-proxy/src/lib.rs#L1034-L1040)), while its own sibling sites still hand-map the join ([store.rs L417-L425](https://github.com/windmill-labs/windmill/blob/6186a0645d3f3e92e06b666a6b5774b8af2b488f/backend/windmill-api-npm-proxy/src/store.rs#L417-L425), [docs/mod.rs L68-L79](https://github.com/windmill-labs/windmill/blob/6186a0645d3f3e92e06b666a6b5774b8af2b488f/backend/windmill-api/src/docs/mod.rs#L68-L79)), which is the subject's current state. Svix re-raises the join as the panic it was via `resume_unwind(e.into_panic())` so no variant is chosen at all ([webhook_http_client.rs L683-L690](https://github.com/svix/svix-webhooks/blob/924f07eae5b86f025fbfe5da07a6685148e89798/server/svix-server/src/core/webhook_http_client.rs#L683-L690)). mistral.rs classifies through a source-chain walk, `ApiError::from_error` with `find_error::<E>`, giving Internal-or-worse kinds a fixed leak-safe message ([handler_core.rs L131-L166](https://github.com/EricLBuehler/mistral.rs/blob/d5ae0f18f2170f10d30880cb7d21fb0880410e7b/mistralrs-server-core/src/handler_core.rs#L131-L166), [L305-L313](https://github.com/EricLBuehler/mistral.rs/blob/d5ae0f18f2170f10d30880cb7d21fb0880410e7b/mistralrs-server-core/src/handler_core.rs#L305-L313)). Windmill additionally puts `#[track_caller]` on every `From<LibError> for Error` impl so the variant carries file:line for free ([error.rs L146-L193](https://github.com/windmill-labs/windmill/blob/6186a0645d3f3e92e06b666a6b5774b8af2b488f/backend/windmill-common/src/error.rs#L146-L193)).

In the subject this replaces eleven `.map_err(|join| GatewayError::Xxx(Box::new(join)))` sites across `config_write.rs`, `env_file.rs`, `config_apply.rs`, `commands.rs`, `admin/profiles.rs`, `reveal.rs`, plus `GatewayError::cache` doing the same job in `model_info.rs`, choosing among six variants for what is always a panicked or cancelled task.

The fix: one `pub(crate) async fn blocking<T>(work: impl FnOnce() -> T + Send + 'static) -> Result<T, GatewayError>` in `error.rs` that maps the join to a single internal variant (or, following Svix, resumes the unwind when `is_panic()`), and every site becomes `blocking(move || ...).await?`. Confidence: high - small, mechanical, and every reference that centralizes it is cleaner at those sites than the ones that do not.

### Finding 4: A typed loopback-tier extractor beside `AuthedCaller`

Svix expresses each auth tier as its own `FromRequestParts<AppState>` extractor, `permissions::Organization`, `::Application`, `::ReadAll`, `::OrganizationWithApplication`, so the handler signature names its tier and loads the scoped resource in one step ([permissions.rs L17-L152](https://github.com/svix/svix-webhooks/blob/924f07eae5b86f025fbfe5da07a6685148e89798/server/svix-server/src/core/permissions.rs#L17-L152)); an admin handler simply takes the admin tier ([admin.rs L12-L15](https://github.com/svix/svix-webhooks/blob/924f07eae5b86f025fbfe5da07a6685148e89798/server/svix-server/src/v1/endpoints/admin.rs#L12-L15)).

In the subject, `AuthedCaller` in `auth.rs` already does this for the bearer tier, but the loopback tier exists only as the `route_layer(from_fn(require_loopback))` at `lib.rs` line 606; a walled handler's signature is indistinguishable from an open one.

The fix: a `LoopbackCaller` (or `WalledCaller`) extractor wrapping `AuthedCaller` plus the loopback check, used by every handler under the walled directory from Finding 1; keep the `route_layer` wall as defense in depth so a handler placed in the wrong directory still fails closed. Confidence: medium - single reference, but it extends a mechanism the subject already trusts.

### Finding 5: Typed response structs for the admin surface

SGLang's worker service returns a typed error enum with `error_code()`, `status_code()`, and `IntoResponse`, plus typed success structs such as `CreateWorkerResult` that render 202 with a `Location` header, so the axum handler is a two-arm match ([worker_service.rs L25-L110](https://github.com/sgl-project/sglang/blob/745de73ba3c136b6f99b7a3e2177ed1a8eef4a56/sgl-model-gateway/src/core/worker_service.rs#L25-L110), [server.rs L413-L421](https://github.com/sgl-project/sglang/blob/745de73ba3c136b6f99b7a3e2177ed1a8eef4a56/sgl-model-gateway/src/server.rs#L413-L421)). llm-gateway-rs keeps a Row / Info / Created DTO triple per entity with secret-dropping `From` impls, so the response shape is a type ([provider.rs L48-L91](https://github.com/poly-workshop/llm-gateway-rs/blob/a580c58d3ae9af06b90632b25b03c6223e74f01d/src/models/provider.rs#L48-L91), [user_key.rs L6-L55](https://github.com/poly-workshop/llm-gateway-rs/blob/a580c58d3ae9af06b90632b25b03c6223e74f01d/src/models/user_key.rs#L6-L55)). Svix goes furthest with typed error bodies ([error.rs L267-L304](https://github.com/svix/svix-webhooks/blob/924f07eae5b86f025fbfe5da07a6685148e89798/server/svix-server/src/error.rs#L267-L304)) and a proc macro that fails compilation on an undocumented handler ([aide.rs L48-L83](https://github.com/svix/svix-webhooks/blob/924f07eae5b86f025fbfe5da07a6685148e89798/server/svix-server-derive/src/aide.rs#L48-L83)); that far end is not recommended here.

In the subject this replaces the `serde_json::json!` reply literals in `admin/status.rs`, `admin/profiles.rs`, `config_apply.rs`, `config_pending.rs`, and `env_file.rs`, whose shape the config UI depends on and only the integration tests pin.

The fix: one `Serialize` struct per admin reply in the module that produces it (the SGLang and llm-gateway-rs shape), leaving the wire JSON byte-identical; the integration tests then double as shape tests against a type. Confidence: medium - three references converge, but the payoff is maintainability rather than a defect today.

### Finding 6: A typed route registry with a tier kind, pinned by a test, replacing the doc paragraph

mistral.rs declares every route as a `pub const RouteInfo { path, methods, kind }` in one registry file with a unit test pinning slice membership ([route_registry.rs L1-L175](https://github.com/EricLBuehler/mistral.rs/blob/d5ae0f18f2170f10d30880cb7d21fb0880410e7b/mistralrs-server-core/src/route_registry.rs#L1-L175)); every route but `/metrics` binds a `*_ROUTE.path` constant rather than a literal ([mistralrs_server_router_builder.rs L375-L427](https://github.com/EricLBuehler/mistral.rs/blob/d5ae0f18f2170f10d30880cb7d21fb0880410e7b/mistralrs-server-core/src/mistralrs_server_router_builder.rs#L375-L427)), and the binary logs the mounted routes grouped by kind at startup ([serve.rs L269-L300](https://github.com/EricLBuehler/mistral.rs/blob/d5ae0f18f2170f10d30880cb7d21fb0880410e7b/mistralrs-cli/src/commands/serve.rs#L269-L300)).

In the subject this replaces the 80-line crate-root doc paragraph at `lib.rs` lines 9-81 that enumerates every route in prose and drifts from the table beneath it, and the literal path strings in `build_router`.

The fix: after Finding 1, each area module declares its `RouteInfo` consts with a tier kind and binds them in its `routes()`; one test walks the assembled router's registered paths and asserts each is registered under the kind its module directory claims. The doc paragraph shrinks to the tier model and a pointer at the registry. Confidence: medium - single reference with a strong human signal, and it composes with rather than competes against decentralization.

### Finding 7: Thin handlers over transport-free command functions; split `config_apply.rs`

SGLang keeps axum handlers as thin wrappers that unpack extractors and call area functions taking `&AppContext` plus a typed request ([server.rs L472-L516](https://github.com/sgl-project/sglang/blob/745de73ba3c136b6f99b7a3e2177ed1a8eef4a56/sgl-model-gateway/src/server.rs#L472-L516) calling [tokenize/handlers.rs L80](https://github.com/sgl-project/sglang/blob/745de73ba3c136b6f99b7a3e2177ed1a8eef4a56/sgl-model-gateway/src/routers/tokenize/handlers.rs#L80)). llm-gateway-rs's service functions take a pool and return `Result<T, AppError>` with no HTTP knowledge, and the route handler is an adapter ([key_service.rs L36-L41](https://github.com/poly-workshop/llm-gateway-rs/blob/a580c58d3ae9af06b90632b25b03c6223e74f01d/src/services/key_service.rs#L36-L41), [admin.rs L34-L46](https://github.com/poly-workshop/llm-gateway-rs/blob/a580c58d3ae9af06b90632b25b03c6223e74f01d/src/routes/admin.rs#L34-L46)). Windmill's extraction seam is a forwarder module: a bare `pub use` ([groups.rs L1](https://github.com/windmill-labs/windmill/blob/6186a0645d3f3e92e06b666a6b5774b8af2b488f/backend/windmill-api/src/groups.rs#L1)) or a wrapper that re-exports and adds the one route needing crate-internal state ([scripts.rs L10-L25](https://github.com/windmill-labs/windmill/blob/6186a0645d3f3e92e06b666a6b5774b8af2b488f/backend/windmill-api/src/scripts.rs#L10-L25)).

In the subject this addresses `config_apply.rs` (over 1,000 lines), which holds the `admin_config_apply` and `admin_config_revert` routes, the `apply_config` command body, and their tests in one file.

The fix: move `apply_config` and its snapshot types beside the other commands in `commands.rs` or a `commands/apply.rs`, leaving `config_apply.rs` as two thin handlers; do the same for any other route file whose body is a command. Confidence: medium - two references converge, but the split touches the apply lock discipline and needs the integration suite as the invariant.

### Finding 8: A builder for `AppState` assembly

SGLang builds its context through `AppContextBuilder` as the only constructor: `from_config` chains `with_*` steps and `build()` names the missing field ([app_context.rs L72-L90](https://github.com/sgl-project/sglang/blob/745de73ba3c136b6f99b7a3e2177ed1a8eef4a56/sgl-model-gateway/src/app_context.rs#L72-L90), [L227-L309](https://github.com/sgl-project/sglang/blob/745de73ba3c136b6f99b7a3e2177ed1a8eef4a56/sgl-model-gateway/src/app_context.rs#L227-L309)), and its tests reuse the builder with in-memory storage before calling the production `build_app` ([test_app.rs L66-L119](https://github.com/sgl-project/sglang/blob/745de73ba3c136b6f99b7a3e2177ed1a8eef4a56/sgl-model-gateway/tests/common/test_app.rs#L66-L119)). mistral.rs returns a finished `Router` from a builder the binary nests beside its own routers ([mistralrs_server_router_builder.rs L282-L321](https://github.com/EricLBuehler/mistral.rs/blob/d5ae0f18f2170f10d30880cb7d21fb0880410e7b/mistralrs-server-core/src/mistralrs_server_router_builder.rs#L282-L321), [serve.rs L151-L210](https://github.com/EricLBuehler/mistral.rs/blob/d5ae0f18f2170f10d30880cb7d21fb0880410e7b/mistralrs-cli/src/commands/serve.rs#L151-L210)).

In the subject this addresses `AppState::from_parts` in `lib.rs` (nine parameters, three of them feature-gated, behind a `too_many_arguments` waiver) and the `state_over` and `loopback_state` helpers in the test support that rebuild it by hand.

The fix: an `AppStateBuilder` with `with_*` steps for the feature-gated parts and the injectable seams (`hf`, `reveal`, `park`), used by `runner.rs` and by the test harnesses. Confidence: low - two references converge, but `runner.rs`'s length is mostly the serve loop rather than assembly, so the file-size payoff is small.

## Refactor notes

- Findings 1, 2, 3, 6, and 8 are pure structure: the wire behavior of every route, including its status and error envelope for a malformed query or path, must be byte-identical before and after. Finding 4 adds a second check on walled handlers that the existing `route_layer` already enforces, so behavior is unchanged when both are present. Finding 5 changes the serializer, not the JSON. Finding 7 moves a command body across a lock boundary and is the one step where behavior could shift; keep the apply mutex acquisition in the same relative position.
- The integration suite under `tests/it/` plus the in-process loopback and auth tests are the invariant. They move last, and only to follow a renamed module path, never to change an assertion.
- Do not touch: `dialect.rs` and `routing.rs` (large but single-purpose), `tray/` (per-platform by necessity), the `shared-loopback` wall implementation, the STT and config-ui crate boundaries (already the target shape), and the `GatewayError::classify()` table.
- Per step: `cargo clippy --all-features` clean under the crate's deny set, `cargo test -p gateway` green, then commit with the finding number in the message.
