# Runvil: Engine, Harness, Events, and Replay

Report type: evaluation / review. It judges Runvil's prompt executor against 6 popular codebases sharing the sans-IO engine and agent-harness technique, and prescribes idioms to adopt, in payoff order.

## Executive summary

Runvil already has the hard part right and the easy part wrong: its script boundary is a closed, validated effect protocol that four of six references would envy, but the scheduler around it spawns tokio, holds a concrete HTTP client, reports through five callbacks, and keeps no record a run could be resumed from. The references converge on one answer: an engine that is a step function over typed inputs and outputs, a harness that performs every effect and writes every effect, answer, and event to an append-only log with a per-effect identity, and subtasks that are addressable processes rather than anonymous chains. The top finding, journaled effects with a replay identity and a nondeterminism/fatal error split, is what turns the existing protocol into a replayable and resumable run, and it is the one every durable-execution reference (Temporal, lash, everruns) builds first.

### Key findings

1. **Journal every effect under a per-effect replay identity and distinguish "history disagrees" from "history is corrupt" (Temporal sdk-core, lash, everruns, zed, paigasus-helikon).** Six references log effects and answers with a stable key; Temporal's two-kind error taxonomy is what makes replay safe to trust. Runvil records nothing. Confidence: high.
2. **One typed input stream and one typed output stream; the engine steps with no runtime (str0m, lash, everruns, paigasus-helikon, zed).** Five references return effects and events as values from a pure step; Runvil returns requests as values but delivers events through five callbacks and spawns its own tasks. Confidence: high.
3. **Cancellation must leave a record the model and the replayer can read (zed, paigasus-helikon, lash).** Synthesize an answer for every dangling call; re-emit an outstanding effect exactly once on restore. Runvil's cancel drops the conversation. Confidence: high.
4. **Model transport behind a trait outside the core with a scriptable fake (lash, zed, paigasus-helikon).** Three references keep reqwest out of every core manifest and step the tool loop from tests as the provider. Runvil's `RunContext` holds the reqwest client. Confidence: high.
5. **Subtasks as addressable processes with a lifecycle policy, a depth cap, and recursive cancellation (lash, zed, everruns, paigasus-helikon).** Runvil's chains have ids only inside the scheduler and its `CancelHandle::child()` is never called. Confidence: high.
6. **Time is an input; the engine holds no clock (str0m, paigasus-helikon, everruns).** Confidence: high.
7. **Architecture guards that read manifests and source, plus a clippy ban on `tokio::spawn` in the core (lash, everruns, paigasus-helikon, str0m).** Runvil already has the harness for this in `build-xtask`. Confidence: high.
8. **Runtime-free conformance tests: lockstep restore, incremental-versus-replay pairing, virtual-clock harness (everruns, Temporal, str0m, zed).** Confidence: high.
9. **Versioned behavior flags recorded in the log (Temporal sdk-core).** Lets the engine change behavior without breaking replay of old runs. Confidence: medium.
10. **A three-state lifecycle and one shared "terminal beats late cancel" rule (str0m, paigasus-helikon).** Collapses the host's hand-juggled run bookkeeping. Confidence: medium.

## Method

The subject was profiled first through nine lenses (module decomposition, state ownership, boundaries, error shape, resource lifecycle, testing, comment policy, build and delivery, messes), yielding eight named deficits and five strengths. The field was surveyed for Rust agent runtimes, sans-IO protocol libraries, durable-execution kernels, and editor agent panels; 22 candidates were gathered and 17 verified against manifests or source, with two local checkouts (everruns, zed) included by request. Six references were dived in parallel at pinned commits through the same nine lenses. Every cited idiom was then dated: commit history was scanned for AI markers, each cited file was walked with rename-following, and where an AI-marked commit touched a cited file the mechanism at HEAD was compared against its last pre-AI form. Findings were ranked by deficit severity, then convergence across references, then adoption cost, and 70 citations were checked against the pinned clones; 67 passed as written and 3 were corrected to their actual locations.

## Baseline: where the subject stands

Runvil is a Rust workspace (about 95 percent Rust, with two embedded Lua shim files) whose executor ships as two public crates, `runvil-api-runtime` and `runvil-api-types`, consumed by a gateway binary and a Tauri desktop app. Key dependencies are `mlua` (Lua 5.5), `tokio`, `reqwest`, `serde`, `axum` in the host, with `cargo-hakari` unification and a `build-xtask` crate that enforces the crate tier graph as a test. Lua sections `coroutine.yield` request tables; one stack-owned `Scheduler` validates them into a `Request` enum, spawns leaf tasks, and resumes with `Answer<E>`. The host injects an observer, an input broker, delta and `ui()` closures, a gateway client, and a cancel handle into `RunContext`. A pure `transition(state, event) -> (state, effect)` reducer supervises relaunch, cancel, and close.

Strengths the field confirms: effects-as-data at the script boundary with a closed enum validated once and the `coroutine` global stripped (`crates/runvil/lua/src/protocol.rs`, `coro.rs`, `__impl_coro.lua`); a single-owner scheduler with no `Arc` or `Mutex` in the driver and an id-indexed chain arena (`crates/runvil-api-runtime/src/execute/scheduler.rs`); structural cancellation polled at the Lua instruction hook, between steps, and while suspended, with exactly-once terminal observations (`crates/runvil-api-types/src/cancel.rs`, `fanout/arm.rs`); a pure supervisor reducer over `Copy` types (`crates/workshop/sessions/src/agents/supervisor/transition.rs`); and test-enforced architecture tiers (`crates/build-xtask/src/product.rs`).

Deficits the findings map to:

1. No replayable run log or resumable state: observations are write-only callbacks, the request/answer stream is never recorded, and a turn-cancel relaunch restarts the chat agent with a fresh message list (`crates/workshop/sessions/src/agents.rs`, `agents/chat.md`, `execute/config.rs`).
2. A concrete reqwest `GatewayClient` in the core: `RunContext.client`, `GatewaySource::Env` built from environment variables inside the executor, no transport trait (`execute/gateway.rs`, `execute/tool_loop.rs`).
3. The engine spawns tokio tasks itself (`scheduler.rs` at four dispatch sites), so the state machine cannot be stepped without a runtime.
4. Effects and events are asymmetric: requests are typed data, but observation, deltas, `ui()`, input, and cancel are five callbacks or trait objects on `RunContext` (`execute/config.rs`).
5. Subtasks are uninspectable: `ChainId`s exist only inside the scheduler; a host cannot list, wait on, or cancel a `call` or `fanout` chain; `CancelHandle::child()` is documented for subagents and never called.
6. Two protocol-bearing files over 2,400 lines with five or more roles each (`scheduler.rs`, `protocol.rs`).
7. Retired-design residue: `Request::Chat`, `install_agent_chat_shim`, `install_runtime_events` with no caller, 90-plus "legacy engine" comment anchors.
8. Manual host bookkeeping beside the pure reducer: `EffectExecutor` hand-juggles `active_run.take()`, `finish_run`, generation counters, and two snapshot pairs (`supervisor/effects.rs`).

### Finding 1: Journal every effect under a per-effect replay identity, and split "history disagrees" from "history is corrupt"

Every durable reference gives each effect a stable identity before it leaves the engine and writes the effect and its answer to an append-only journal keyed by that identity. lash wraps every command in a `RuntimeEffectEnvelope` whose invocation carries a replay key and whose `stable_hash()` is the replay fence, and routes all of them through one `RuntimeEffectController::execute_effect` trait that in-memory, SQL, and Restate hosts implement alike (lash `crates/lash-core-execution/src/runtime/effect/envelope.rs#L190-L280`, `#L352-L420`; `crates/lash-core-execution/src/runtime/effect/executor/control.rs#L328`, `#L370`; `crates/lash-sansio/src/effect_identity.rs#L14-L32`, `#L166-L206`). Temporal treats the ordered queue of commands the workflow emitted as the replay oracle: each history event pops the front, an empty queue or a rejected event is nondeterminism, and `replaying` flips to false at the first event the SDK could not have produced (Temporal `crates/sdk-core/src/worker/workflow/machines/workflow_machines.rs#L926-L989`, `#L1115-L1141`, `#L664-L683`). Its error taxonomy is the part to copy exactly: `Nondeterminism` when the code's commands disagree with recorded history, `Fatal` when the history or the engine's bookkeeping is malformed, with the same invalid transition classified one way in `handle_command` and the other in `handle_event` (Temporal `crates/sdk-core/src/worker/workflow/mod.rs#L1706-L1752`; `crates/sdk-core/src/worker/workflow/machines/mod.rs#L130-L174`). everruns adds at-most-once tool execution through a claim/settle compare-and-swap that returns `Claimed`, `AlreadySettled`, `AlreadyRunning`, or `DeterminismViolation` (everruns `crates/core/src/durability.rs#L7-L89`). zed persists the message list as the only durable state and replays the event stream from it, with each tool re-rendering from stored raw output rather than re-running (zed `crates/agent/src/thread.rs#L1512-L1676`, `#L5150-L5159`; `crates/agent/src/agent.rs#L1650-L1660`). paigasus-helikon's session is an append-only event log folded by a recorder, and resume is literally `run` with empty input (paigasus-helikon `crates/paigasus-helikon-core/src/session.rs#L50-L58`, `#L400-L545`; `crates/paigasus-helikon-core/src/runner.rs#L139-L158`).

What it replaces: Runvil's `Request`/`Answer` stream is produced and consumed in `crates/runvil-api-runtime/src/execute/scheduler.rs` and never written anywhere; observations go to a write-only `Observer` and the Workshop's JSONL session log (`crates/workshop/sessions/src/session-log.rs`) records events but not effects or answers. The fix: give every effect an `Origin { task, seq }` at emission, have the harness append `(origin, effect)` and `(origin, answer)` rows beside events, and adopt Temporal's two-kind error split for the future replay matcher. Confidence: high, six references converge and the two load-bearing mechanisms are human-authored at Temporal and pre-AI at lash.

### Finding 2: One typed input stream and one typed output stream; the engine steps without a runtime

str0m states the contract in its crate doc and holds to it across five sub-machines: the host mutates through `&mut self`, drains `poll_output` until `Output::Timeout`, waits, and repeats; boundary records derive serde and are transport-free, and an output can re-enter as input through `TryFrom` (str0m `src/lib.rs#L117-L159`, `#L1075-L1096`, `#L1549-L1576`, `#L1960-L1973`, `#L1906-L1934`; `crates/proto/src/net.rs#L119-L171`; `src/io/mod.rs#L37-L104`, `#L153-L164`). lash's `TurnMachine` exposes `poll_effect()` and `handle_response()` and its harness is one `while let Some(effect)` loop (lash `crates/lash-sansio/src/sansio/turn_machine.rs#L222-L245`, `#L352-L456`; `crates/lash-core/src/runtime/turn_driver/machine.rs#L82-L164`). everruns' planner takes `now` and pre-resolved host facts as parameters and returns a plan plus an ordered effect list applied by one host match, while live deltas that cannot wait go through a small sink trait applied immediately (everruns `crates/engine/src/turn.rs#L84-L135`, `#L275-L312`; `crates/host/src/turn_strategy.rs#L184-L247`; `crates/engine/src/phase_effects.rs#L1-L38`, `#L72-L87`). paigasus-helikon's `transition` returns next state, events, next action, and conversation appends together, and its Temporal driver is a mechanical loop over it (paigasus-helikon `crates/paigasus-helikon-core/src/loop_state.rs#L160-L227`; `crates/paigasus-helikon-runtime-temporal/src/driver.rs#L47-L66`, `#L176-L254`). zed returns a single `ThreadEvent` stream and folds authorization and elicitation into it as variants carrying a reply channel, consumed by the same host function that consumes replayed history (zed `crates/agent/src/thread.rs#L872-L889`, `#L1152-L1181`; `crates/agent/src/agent.rs#L2163-L2338`).

What it replaces: the four `tokio::spawn`/`spawn_blocking` sites and the `mpsc` answer channel in `scheduler.rs`, and the five host callbacks on `RunContext` in `execute/config.rs`. The fix: `Run::step() -> Pending { effects, events } | Done`, `Run::resume(id, answer)`, with `Event` as one enum replacing `Observer` and `DebugCapture`; deltas belong to the harness because it performs the model call. Confidence: high, five references converge and the str0m contract is human-authored.

### Finding 3: Cancellation must leave a record the model and the replayer can both read

zed's `flush_pending_message` inserts a sentinel error result for every unanswered tool call so the persisted log stays valid for the model, replay filters the sentinel, and `Stop(Cancelled)` is the terminal event (zed `crates/agent/src/thread.rs#L72`, `#L3990-L4024`, `#L1575-L1580`). paigasus-helikon's recorder synthesizes `ToolReturned` for dangling calls on cancel (paigasus-helikon `crates/paigasus-helikon-core/src/session.rs#L400-L545`). lash makes the machine itself checkpointable: every waiting state carries an `EffectDelivery { id, status }` whose status is skipped by serde, `checkpoint()` resets it so a restore re-emits the outstanding effect exactly once, and a schema version refuses stale shapes (lash `crates/lash-sansio/src/sansio/machine_state.rs#L1-L43`, `#L81-L135`, `#L216-L228`).

What it replaces: Runvil's turn cancel drops the in-Lua conversation and relaunches from an empty message list. The fix: when an effect is dropped, record a synthesized answer against its origin so the log ends model-valid, and let the future resume path supply a substituted answer for the effect the task was cancelled inside. Confidence: high, three references and two of the mechanisms predate or postdate AI touches by unmarked human commits.

### Finding 4: Model transport behind a trait outside the core, with a scriptable fake for tests

lash's `Provider` trait carries `complete`, `route_identity`, and `generation_retry_guarantee`; its typed transport error with a retry verdict lives in the HTTP transport crate, and reqwest appears in no core manifest (lash `crates/lash-core-llm/src/provider/traits.rs#L39-L109`; `crates/lash-http-transport/src/error.rs#L56-L70`; `crates/lash-core-llm/Cargo.toml`). zed reads `Arc<dyn LanguageModel>` on every loop iteration and ships a `FakeLanguageModel` whose tests step the loop as the provider through `pending_completions`, `send_completion_stream_event`, and `end_last_completion_stream`, with live tests behind an `e2e` feature (zed `crates/language_model/src/language_model.rs#L196`; `crates/language_model/src/fake_provider.rs#L199-L274`; `crates/agent/src/thread.rs#L2825-L2834`). paigasus-helikon puts retry as a model decorator and cancel or deadline as a stream wrapper in the runtime crate, keeping the core manifest free of tokio except for the cancellation token type (paigasus-helikon `crates/paigasus-helikon-runtime-tokio/src/retry.rs#L1-L6`; `crates/paigasus-helikon-runtime-tokio/src/lib.rs#L39-L75`; `crates/paigasus-helikon-core/src/runner.rs#L167-L186`).

What it replaces: `RunContext.client`, `GatewaySource::Env`, and the direct `GatewayClient` parameters in `execute/gateway.rs` and `execute/tool_loop.rs`. The fix: the harness performs `Effect::Chat`; the engine holds only the message and completion vocabulary; the test-support driver answers `Chat` effects from canned completions the way zed's fake does. Confidence: high, three references and zed's fake provider is unmarked since 2024.

### Finding 5: Subtasks as addressable processes with a lifecycle policy, a depth cap, and recursive cancellation

lash mints a durable process id `process:subagent:{call_id}` inside the journaled prepare payload, declares a `RecoveryContract` and a `ProcessLifecyclePolicy { parent_scope, OnParentEnd }`, waits on it by key, and keeps `Abandoned` as a terminal state distinct from `Cancelled` and `Failed` (lash `crates/lash-subagents/src/rlm.rs#L38-L95`, `#L147-L166`; decision records `docs/adr/0094-*.md`, `docs/adr/0095-*.md`). zed returns `Rc<dyn SubagentHandle>` with `id`, `num_entries`, and `send`; persists `SubagentContext { parent_thread_id, depth }` with a cascading delete; refuses creation past `MAX_SUBAGENT_DEPTH` and omits the spawn tool from the child's tool set; the parent holds weak references and `cancel()` recurses into children first; and a token-usage subscription auto-cancels a child that crosses the context warning (zed `crates/agent/src/thread.rs#L143-L149`, `#L746-L801`, `#L2185-L2187`, `#L2272-L2277`; `crates/agent/src/agent.rs#L3084-L3132`, `#L3364-L3482`; `crates/agent/src/db.rs#L506-L509`, `#L677-L711`). everruns keeps a uniform subtask record with a six-state machine, a pure `apply_task_update` reducer with attempt fencing and terminal finality, a control plane split from a report plane, `task.*` snapshot events on the parent's stream, and a per-session wake queue with a documented exactly-once claim point (everruns `crates/core/src/session_task.rs#L57-L72`, `#L374-L450`, `#L640-L692`, `#L704-L819`; `crates/core/src/wake_queue.rs#L1-L36`). paigasus-helikon names its child-context constructors by sharing policy: `handoff_child()` shares session, hooks, cancel, and failure slot; `subagent_child()` gets fresh ones so the parent reads only that child (paigasus-helikon `crates/paigasus-helikon-core/src/context.rs#L283-L342`; `crates/paigasus-helikon-core/src/agent_as_tool.rs#L102-L148`).

What it replaces: `ChainId` as a scheduler-private index in `scheduler.rs`, and the never-called `CancelHandle::child()` in `crates/runvil-api-types/src/cancel.rs`. The fix: a task arena keyed by hierarchical ids, `TaskStarted` events carrying the spawn seeds, an explicit on-parent-end policy (author tasks: error; model tasks: cancel with notice), `Abandoned` distinct from `Cancelled` when the owner ends, `task.*` events on the owner's stream, and a child budget rule the harness can enforce from the log. Confidence: high, four references and the lash and zed mechanisms were added by unmarked human commits.

### Finding 6: Time is an input; the engine holds no clock; each subsystem reports its next deadline

str0m never calls `Instant::now()` in the engine: every subsystem exposes `poll_timeout()`, the root folds them with a three-line `Soonest` trait, clamps to a monotonic `last_now`, tags the winner with a `Reason`, and uses `not_happening()` and `already_happened()` sentinels for never and right-now (str0m `src/util/mod.rs#L16-L35`; `src/lib.rs#L1825-L1854`, `#L1105-L1179`; `src/util/time_tricks.rs#L5-L9`, `#L52-L54`). paigasus-helikon documents `RunConfig.timeout` as runner-scoped because "core has no timer" and puts every deadline wrapper in the runtime crate (paigasus-helikon `crates/paigasus-helikon-core/src/runner.rs#L167-L186`; `crates/paigasus-helikon-runtime-tokio/src/lib.rs#L39-L75`). everruns passes `now` into the planner (everruns `crates/engine/src/turn.rs#L84-L135`).

What it replaces: `now_rfc3339_checked()` called per section entry in `execute/support.rs`, `context.rs`, and `section_context.rs`. The fix: the run start time arrives in `RunContext`, timeouts leave as `Effect::Timer` answered by the harness, and the engine calls no clock. str0m's `poll_timeout` fold is the alternative shape if the engine ever needs to express its own deadlines rather than request them. Confidence: high, three references and the str0m mechanism is human-authored.

### Finding 7: Architecture guards that read manifests and source, plus a clippy ban on `tokio::spawn` in the core

lash runs boundary scripts in a CI gate and adds a crate-local `clippy.toml` `disallowed-methods` entry denying `tokio::spawn` in favour of one span-instrumented wrapper (lash `scripts/check-substrate-boundary.sh#L33-L40`; `crates/lash-core/clippy.toml`; `crates/lash-core-ids/src/task.rs`). everruns writes its guards as ordinary `#[test]`s that read manifests for dependency direction and scan source identifiers after stripping comments and strings (everruns `crates/engine/tests/dependency_direction.rs`; `crates/host/tests/execution_contract_guard.rs#L53-L97`; `crates/core/tests/no_composition_root.rs#L15-L44`). paigasus-helikon keeps workspace-member test crates that enforce cross-cutting conventions with a per-site escape comment (paigasus-helikon `Cargo.toml#L3`; `tests/workspace-lints/src/lib.rs#L1-L50`). str0m exposes engine seams to integration tests through an `_internal_test_exports` feature flipped on by a two-line dummy dev-dependency crate (str0m `Cargo.toml#L121`, `#L176-L177`; `src/_internal_test_exports/mod.rs`).

What it extends: `crates/build-xtask/src/product.rs`, which already enforces the tier graph and container privacy. The fix: a manifest test forbidding `tokio`, `tokio-util`, `async-trait`, and `reqwest` in engine crates' non-dev tables; a `clippy.toml` `disallowed-methods` for `tokio::spawn` in the same crates as a second line; a source-identifier scan that fails when a retired symbol (`install_agent_chat_shim`, `EventsSnapshot`) reappears. Confidence: high, four references and the two cheapest mechanisms are human-authored.

### Finding 8: Runtime-free conformance tests: lockstep restore, incremental-versus-replay pairing, virtual-clock harness

everruns' conformance test drives the in-process and durable drivers in lockstep, restoring the durable one from bytes between every step and asserting plan, effects, and state equality (everruns `crates/worker/tests/execution_conformance.rs#L92-L130`; `crates/engine/src/machine.rs#L21-L108`). Temporal delivers the same canned history as two tasks and as one, through `rstest` cases against a single assertion table (Temporal `crates/sdk-core/src/core_tests/workflow_tasks.rs#L84-L153`; `crates/sdk-core/src/replay/history_builder.rs#L40-L90`). str0m's two-peer harness holds a virtual clock and a timestamped event vector, steps the earliest of four deadlines, and routes each output into the peer's seeded network emulator, running a full handshake with no sockets, sleeps, or runtime (str0m `tests/common.rs#L73-L127`, `#L214-L252`, `#L341-L381`, `#L514-L554`; `crates/netem/src/lib.rs#L61-L177`). zed tiers its model tests between a fake and a live tier behind an `e2e` feature (zed `crates/agent/src/tests/mod.rs`).

What it replaces: about 14,000 lines of `#[tokio::test]` against an axum mock gateway under `crates/runvil-api-runtime/src/execute/tests/` and `tests/suite/`. The fix: a serial `drive(run, perform)` harness in plain `#[test]`s; a pairing test that feeds the same answers in different `step` batchings and asserts identical effects, events, and ids (the engine's Lua state cannot be serialized, so byte-restore lockstep is out, but same-inputs-same-outputs across two independent runs is the analogue); a timestamped event vector as the determinism oracle. Confidence: high, four references and the Temporal and str0m mechanisms are human-authored.

### Finding 9: Versioned behavior flags recorded in the log

Temporal keeps a `#[repr(u32)]` flag set with a reserve-forever rule; `try_use_flag(flag, should_record)` runs new behavior live and records the flag, and on replay honors it only if the original run recorded it, so an engine can change how it behaves without breaking replay of runs recorded before the change (Temporal `crates/sdk-core/src/internal_flags.rs#L10-L38`, `#L96-L118`; `crates/sdk-core/src/worker/workflow/managed_run.rs#L544-L563`).

What it adds: nothing in Runvil records which engine behaviors a run saw. The fix: a `flags` column on the run record and a `try_use_flag` gate around any future exit-rule or protocol change, so old logs stay replayable. Confidence: medium, a single reference and the file's provenance is unknown.

### Finding 10: A three-state lifecycle and one shared "terminal beats late cancel" rule

str0m models `Alive -> Closing -> Closed`: `close()` queues goodbye traffic, handles return `None` while closing, `poll_output` drains to completion then goes inert, fatal errors call `disconnect()` before returning, and a test asserts `UnwindSafe` (str0m `src/lib.rs#L929-L934`, `#L1579-L1582`, `#L1961-L1963`, `#L1975-L2011`, `#L1626-L1631`, `#L2232-L2236`). paigasus-helikon reduces "a genuine terminal beats a late cancel or timeout" to one pure `effective_interrupt(interrupt, saw_terminal)` function, renders the single synthetic terminal frame in one place, and pins every variant with wildcard-free matches and a fixture-coverage test (paigasus-helikon `crates/paigasus-helikon-core/src/runner.rs#L495-L619`, `#L736-L880`).

What it replaces: `EffectExecutor`'s hand-managed `active_run.take()`, `finish_run`, and generation counters in `crates/workshop/sessions/src/agents/supervisor/effects.rs`. The fix: `Run` withholds `Done` while effects are outstanding and goes inert after it, so the host's question reduces to "is it done"; the interrupt rule joins the existing pure `transition` reducer. Confidence: medium, two references and the str0m lifecycle postdates its pre-AI form by an unmarked human commit.
