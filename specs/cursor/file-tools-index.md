# Cursor file tools: index to the twelve reports

This folder holds two sets of six reports, one pair for each of Cursor's six file tools. The **evidence reports** (`tool-*.md`) say what Cursor and eleven other harnesses do. The **master reports** (`master-*.md`) say how Runvil should build each tool in the `plugin-std` crate, and why. This file is the entry point to both: read the master for the tool you are about to build, then the one or two evidence sections that master cites. Where the reports disagree, the shipped bundle beats the parent spec [agent-file-tools.md](agent-file-tools.md), and a master beats its evidence report wherever the master says it departs (the departures are listed in [Where the masters depart from the evidence reports](#where-the-masters-depart-from-the-evidence-reports)). Confidence high, because the masters were reconciled against one set of cross-tool rulings after the evidence reports were finished.

The evidence set is derived from Cursor 3.27.12 on Windows: the 9,814,287-byte minified bundle at `cursor-agent-exec/dist/main.js`, and the unminified 20 MB daemon twin at `cursor-agent-host/dist/agent-host-daemon/dist/bin/daemon.cjs`. Every evidence report labels its claims `(bundle)`, `(daemon)`, `(probe)` for something that was run, `(source)` for another harness's code at a named commit, or `(web)`, so you can tell a read from a measurement from an inference. The masters use the same labels, and mark an assumption with "I assume" and a judgment with "I judge".

## Start here: the six masters

Each row pairs a tool's master with its evidence report. Line counts were taken from the files on 2026-10-28. Confidence in each recommendation is the master's own word, with its reason.

Runvil ships one wire name per tool. A decision that spans tools is stated once, in the next section, and the six masters were edited to agree with it.

## What the masters decided together

Each row is a decision that spans more than one tool: what was decided, the master section that owns it, and the confidence. Every row was checked against the masters as they stand. If a row and a master ever disagree, the master is right and the row is stale. Confidence is the master's.

| Decision | What the masters decided | Owning section | Confidence |
|---|---|---|---|
| Line-number format | Read prefixes every line with a six-wide right-aligned number, a pipe and no space (`     1\|text`), always on, with no argument to turn it off. Grep's content mode keeps Cursor's shape instead: the file's path once, then two spaces, the line number, `:` for a match or `-` for context, and the text, where the number is the one Read prints. Write's `contents` and StrReplace's `old_string` never include a prefix, and StrReplace's refusal excerpts reuse Read's format. | [master-read.md](master-read.md), "Number every line with a six-wide pipe prefix, and say so in the description"; [master-grep.md](master-grep.md), "Render files as grouped lines, let `-A` and `-B` override `-C`, and take context from the same bytes"; [master-str-replace.md](master-str-replace.md), "Name the cause and the next move in every refusal" | Medium - the best-attested format, but no source measures how models cope with any format |
| Read cap and window | Read stops at 100,000 bytes of numbered lines on a line boundary and ends with a trailer that names the next offset; the trailer and any note are not counted. It reads at most 16 MiB plus one byte through the new `Access::read_range` and refuses more. `offset` is a one-based line number, `0` reads as 1, a negative offset counts from the end, a window that overlaps the file is clamped, a window that selects nothing fails, and `limit` below 1 is refused. | [master-read.md](master-read.md), "Stop at a 100,000-byte cap on a line boundary and name the next offset"; "Bound the read with a type check and a 16 MiB ceiling"; "Read a window by one-based offset and limit, and count a negative offset from the end" | Medium - the 100,000 and 16 MiB figures are judgments among harness values |
| File-size ceilings | Read refuses a file over 16 MiB. Grep skips a file over 16 MiB as a counted skip and stops a search at 100,000 files or 1 GiB read. StrReplace refuses a file over 8 MiB before it reads, so a file between 8 and 16 MiB can be read in pages and cannot be edited. Write's gate refuses an overwrite of a file over 16 MiB, because no whole-file record exists for it; a file that grew past 16 MiB after a whole read is loaded with no bound. | [master-read.md](master-read.md), "Bound the read with a type check and a 16 MiB ceiling"; [master-grep.md](master-grep.md), "Order results by full path, and stop by work done instead of by a clock"; [master-str-replace.md](master-str-replace.md), "Refuse files over 8 MiB and bound the match bookkeeping"; [master-write.md](master-write.md), "Risks and open limits" | Medium - four numbers, none measured |
| The read record and who writes it | Read writes one entry per canonical path: the SHA-256 of the raw bytes it returned, the first and last line shown, the line total and `whole` (true only for lines 1 to the total with no cut). A file with no text still gets an entry (0 to 0, total 0, `whole` true). Write gates an overwrite of an existing non-empty file on it (the last read was whole and the hash still matches the disk; a missing path, an empty file and a file holding only a byte order mark need no read), then replaces the whole entry. A successful StrReplace replaces only the hash and creates no entry. StrReplace never gates; on a miss it adds `The file has changed since you last read it.` when the hash differs. The record lives in a required per-run service: `plugin-std` declares the key, the Pack lists it in `needs`, the Host supplies it beside the input broker, and `read-real` ships without it. | [master-read.md](master-read.md), "Publish a read record to a per-run service, and keep the render pure"; [master-write.md](master-write.md), "Refuse to overwrite an existing file the run has not read whole and current"; [master-str-replace.md](master-str-replace.md), "Diagnose a stale edit on a miss and never gate on a read" | Medium - two sibling reports and two harnesses converge, but the service does not exist yet |
| Encoding and binary handling | Read decodes lossily: it drops a UTF-8 mark, decodes UTF-16 by its mark, decodes anything else as UTF-8 with replacement, adds a note that counts replaced sequences, and never returns `NotUtf8`. It refuses a file as binary when any of the first 8,192 bytes is NUL or at least 5% are control bytes other than tab, LF and CR, with no extension list. Grep calls the same shared `text` module (`decode`, `sniff_binary`, `split_lines`), so a Grep line number names the line Read prints. Write and StrReplace refuse an old file that is not valid UTF-8 and name the byte offset, so a file Read shows decoded is read-only through the other two. Glob and Delete read no content. | [master-read.md](master-read.md), "Decode lossily, hide the byte order mark, and say when bytes were replaced"; "Refuse binary content by sniffing the first 8,192 bytes"; [master-grep.md](master-grep.md), "Decode text as UTF-8 with replacement, strip a BOM, and split lines the way Read does"; [master-write.md](master-write.md), "Refuse to rewrite a file that is not valid UTF-8, and write UTF-8 as sent"; [master-str-replace.md](master-str-replace.md), "Refuse a file that is not valid UTF-8 instead of decoding it lossily" | Medium for the decode and its note (the note has no precedent); high for the binary sniff (four harnesses sniff content) |
| Line model | Split on `\n`, drop the empty element after a final newline, strip one `\r` from every line, hide a UTF-8 byte order mark, and read a file whose only terminator is `\r` as one line. A zero-byte file and a file holding only a mark have no lines and answer `File is empty.`. Write counts lines the same way for its reply, keeps a file's mark and uniform CRLF, and stores `contents` as sent, so the final newline is whatever `contents` ends with. StrReplace matches on an LF view in which a lone CR is a break, and numbers its excerpts with Read's splitter. | [master-read.md](master-read.md), "Report the same line total whether or not the file ends in a newline"; "Strip one trailing carriage return from every line"; [master-write.md](master-write.md), "Keep a file's BOM and uniform CRLF, and use LF for a new file"; [master-str-replace.md](master-str-replace.md), "Match on an LF view with the BOM removed and map offsets back to the original" | High for the `\r` strip (nine harnesses agree); medium for the final-newline rule and StrReplace's view |
| List cap and paging notices | Glob and Grep share one cap, 15,000 UTF-8 bytes of body, and the notice lines are not counted; Read's 100,000 stays apart. A cut Glob page ends `[Showing files 1-483 of 1432. Use offset=483 to see more, or narrow the pattern.]`. A cut Grep page ends `[Showing 1-50 of at least 51 matching lines. Use offset=50 to see more, or narrow the search.]`. A notice prints only when something remains, so an exact fit is silent. Grep keeps no cache and re-runs the search for each page. | [master-glob.md](master-glob.md), "Page with `offset` under one byte budget, and print the exact total"; "Print a notice only when paths remain: an exact fit is silent"; [master-grep.md](master-grep.md), "Bound one result with a single byte budget, and cut a long line around its match"; "Page by re-running with `offset`, keep no cache, and name the cause of every cut" | Low for the 15,000 number (no source measures an adequate page); medium for the shape |
| Offset base | Read's `offset` is a one-based line number. Glob's and Grep's `offset` count entries to skip from 0, and each notice prints the exact number to send, so the model never converts. Grep reads `head_limit: 0` as no limit, while Read refuses `limit` below 1; both are Cursor's behavior. | [master-read.md](master-read.md), "Read a window by one-based offset and limit, and count a negative offset from the end"; [master-glob.md](master-glob.md), "Page with `offset` under one byte budget, and print the exact total"; [master-grep.md](master-grep.md), "Count `head_limit` and `offset` globally in entries, with context left out" | Medium - two bases cost one sentence in each description, and no source measures confusion |
| Sort order | Glob sorts by the byte order of the full path string, re-sorts in the Pack and reads no clock. Grep visits each directory's entries keyed by name, with a directory's name followed by `/`, which gives the same order, and stops by files and bytes, never by a clock. | [master-glob.md](master-glob.md), "Sort every result by full-path byte order, with no clock and no budget"; [master-grep.md](master-grep.md), "Order results by full path, and stop by work done instead of by a clock" | High for Glob (Zed, Goose and both Runvil backends already give a total order); medium for Grep (its limits are judgments) |
| Ignore and hidden-path policy | One shared Pack module leaves out any path with a segment named `.git`, file or directory, and every path a `.gitignore` on the way names, honoring `!` rules and needing no `.git` directory. Glob applies it after the match and counts what it left out; Grep applies it during the walk. A directory the model names (`target_directory`, `path`) is searched in both, a pattern never brings an ignored path back, and other hidden files stay visible. The rule hides entries from Glob and Grep listings only: Read, Write, StrReplace and Delete act on any path the call names, and no privacy rule exists in version one. The destination is a per-match filter in `Access`, which deletes the module. | [master-glob.md](master-glob.md), "Put ignore and privacy rules in `Access`, apply them after matching, and count what they hide"; [master-grep.md](master-grep.md), "Prune ignored trees during the walk, never follow a link, and let an explicit `path` win" | Medium - the `ignore` crate against a matcher of his own is open |
| Glob grammar | Only `*` and `**` are special, and `**/` matches zero segments. `{`, `[`, `?` and `!` match themselves, and a zero that holds one gets a hint. Matching is case-sensitive. A relative pattern is searched at any depth (`**/` is prepended), a leading `/` is a full VFS path and is refused beside `target_directory`, and a trailing `/` means the files under that directory. Grep's `glob` filter uses the same grammar through one pure matcher function, and `globset` is not added; `{a,b}` and a case flag reach both tools together when the VFS gains them. | [master-glob.md](master-glob.md), "Accept the grammar `Access::glob` implements, and explain a zero that holds braces, brackets or question marks"; "Make every pattern recursive from the search directory"; "Match case-sensitively and say so"; [master-grep.md](master-grep.md), "Prune ignored trees during the walk, never follow a link, and let an explicit `path` win" | Medium - the cost is that `*.{ts,tsx}` and `*.JS` stop working until the VFS grows both |
| Path form | Glob and Grep print absolute `/`-rooted virtual paths, bare, one per line, and leave out a name with a control character and count it. Every tool accepts a relative path, joins it onto `/` and advertises the absolute form. A message echoes the argument as the model wrote it, never the canonical path. A blank or whitespace-only `path` is refused by one shared helper in Read, Write, StrReplace and Delete; Glob and Grep read an empty `target_directory` or `path` as absent. A backslash in `target_directory` is read as `/`. | [master-glob.md](master-glob.md), "Print absolute VFS paths, bare, one per line, and leave out any name with a control character"; [master-read.md](master-read.md), "Name the path and the next step in every failure"; [master-delete.md](master-delete.md), "Refuse an empty, whitespace-only or root path before any I/O" | High - Cursor's relative form fails the copy test, and VFS paths are short and the same on every host |
| Failure-message rules | A message names the path as the model wrote it and the next step, and names no other tool. The one exception is Write's read-gate refusal, which has to say to read; a description may name another tool. A zero or a skip says why. A missing file reads `File not found: {path}` (Read, StrReplace); a missing search root reads `Path does not exist: {path}` (Glob, Grep). | [master-read.md](master-read.md), "Name the path and the next step in every failure"; [master-write.md](master-write.md), "Name the path and the next step in every refusal"; [master-glob.md](master-glob.md), "Render every `VfsError` in one function that names the rule, the path and the next step" | High - Cursor's omissions are observed in the bundle |
| One Conflict sentence per tool | Each tool tells the model to retry "in your next message". Read: `{path} was changed, or is being changed, by another call in this round, so it cannot be read in this round. Call Read again in your next message.` Glob: `A path that "{pattern}" matches is held by another call in this round, so this search cannot run in this round. Call Glob again in your next message.` Write and Delete: `{path} is also used by another call in this round (a read, write, glob, grep, list or delete that covers it), so it cannot be changed in this round. Send this call again in your next message.` (Delete says "removed"). StrReplace: the same opening up to the closing parenthesis and a full stop, then ``Send one StrReplace per file per round, put the edits in one `edits` call, or send this edit in your next message.`` Grep turns a conflict into a counted skip with the reason `another call in this round`. A claim holds until its scope ends, so a finished sibling still conflicts. A `Conflict` the Pack maps to a `ToolError` reaches the model as failure text and does not end the run (read from source, not run). | [master-read.md](master-read.md), "Turn a sibling conflict into a retry instruction and never retry inside Read"; [master-write.md](master-write.md), "Leave concurrent calls to the claims system and report the conflict"; [master-str-replace.md](master-str-replace.md), "Refuse, do not wait, when a sibling call holds the path"; [master-delete.md](master-delete.md), "Claim the canonical path and add no lock of the Pack's own"; [master-glob.md](master-glob.md), "Render every `VfsError` in one function that names the rule, the path and the next step"; [master-grep.md](master-grep.md), "Skip what cannot be searched, count it by reason, and name the first five" | Medium - the claims rule is documented, but no two-call round has been run |
| The shared refusal function | One function, `refusal(tool, given_path, &VfsError) -> String` in `plugin-std`, builds every `VfsError` sentence for all six tools. It passes the policy's reason through unchanged for `PermissionDenied` and `ApprovalRequired`, and ends in a `Display` arm so a variant added later still reads as text. It is the todo `refusal-text`, before `read-real`. The Plan and Ask next-step text moves into the VFS policy reason (`vfs-mode-text`), and the `approval` todo then only wires real approval. | [master-read.md](master-read.md), "Name the path and the next step in every failure"; [master-write.md](master-write.md), "Name the path and the next step in every refusal"; [master-delete.md](master-delete.md), "Keep the policy's reason and render every refusal in one place"; [master-glob.md](master-glob.md), "Render every `VfsError` in one function that names the rule, the path and the next step" | Medium - the need is certain; the function's shape and the todo id are proposals |
| Argument errors and unknown parameters | One helper builds every argument error as ``std_{Wire}: `{name}` {problem}``. The shared check passes undeclared keys through, so each body refuses them with ``std_{Wire}: `{name}` is not a parameter of this tool. The parameters are `a`, `b` and `c`.`` (the helper is `refuse_unknown` in `check.rs`). Read changes `offset` and `limit` to `integer` and reads `null` as absent. Grep keeps the hyphenated names with no aliases, accepts `-n: true`, refuses `-n: false`, and does no coercion. | [master-read.md](master-read.md), "Validate arguments in the body: integers, a limit of at least 1, no undeclared parameters"; [master-grep.md](master-grep.md), "Publish the corrected schema, add `literal`, and refuse any other key by name"; [master-glob.md](master-glob.md), "Refuse an empty pattern and check the target directory before the walk"; [master-delete.md](master-delete.md), "Take one path per call"; [master-write.md](master-write.md), "Name the path and the next step in every refusal"; [master-str-replace.md](master-str-replace.md), "Name the cause and the next move in every refusal" | Medium - the silent case is shown only for Glob's `path`, and the helper is small |
| Link behavior | Read, Write and StrReplace follow a link that stays inside the run's filesystem and refuse one that leaves it (Write and StrReplace also refuse a dangling one). Delete removes the name, never follows the leaf, and says a link went. Glob's walk enters no linked directory and lists no link, though a `target_directory` that names an in-root directory link is walked through. Grep never follows a link met in the walk, counts it as a skip, and searches through a link named as `path`. | [master-read.md](master-read.md), "State every limit in the description and pin the text with a test"; [master-delete.md](master-delete.md), "Remove the name at the path and never follow a link"; [master-glob.md](master-glob.md), "List files only, leave links unlisted, and read `X/` as the files under X"; [master-grep.md](master-grep.md), "Prune ignored trees during the walk, never follow a link, and let an explicit `path` win" | High for Delete (a junction probe shows both rivals fail); medium for the rest - read from source, and the file-link tests are ignored on Windows |
| The per-model tool set | One set for every model, and one wire name per tool, with no per-family variants. Cursor withholds StrReplace and Write from GPT-5-family models and offers `ApplyPatch` instead; `Pack::render` can do the same later, but it must drop `StrReplace` and `Write` together, because Write is gated on a whole read and a model with Write and no edit tool cannot change a large file. | [master-str-replace.md](master-str-replace.md), "Offer one tool to every model, because the Pack system can reshape the set later"; [master-write.md](master-write.md), "Where Runvil should differ from Cursor" | Medium - no measurement either way |
| Mode and approval behavior | Ask refuses every mutation (`ApprovalRequired`). Plan allows a mutation only when the single gated path ends in `.md`, case-sensitively. Read, Glob and Grep are allowed in every mode, so only a custom policy refuses them. Write and StrReplace call `Access::check_write` first, so the refusal comes before the read gate and before any match result. Delete stats first and answers an absent path with a success before `remove` runs, so no prompt appears for a path that is not there. A recursive Delete gates only its top path until `vfs-plan-subtree` lands. Real approval is the `approval` todo. | [master-write.md](master-write.md), "Write through one `Access::write` and let the VFS own atomicity and parent creation"; [master-str-replace.md](master-str-replace.md), "Own the matching in the Pack as a pure function over text"; [master-delete.md](master-delete.md), "Answer an absent path with a success that opens with "Nothing was deleted""; "Refuse a directory that has entries unless the call sets `recursive: true`" | Medium - the name and shape of `check_write` are proposals |
| Trust marking | Read, Glob and Grep mark any reply that holds a path or file text untrusted, because the model did not write the names; a Glob zero reply that holds only the model's own pattern and the hints may be trusted. StrReplace's refusal excerpts reach the model as untrusted failure text, and its success text holds no file text. Write and Delete return their replies as trusted text, because the replies hold only the caller's path, counts and fixed words. | [master-write.md](master-write.md), "Tell the model whether the call created or replaced, and how many lines it replaced"; [master-delete.md](master-delete.md), "Reply with one line that names what went: kind, path and size"; [master-read.md](master-read.md), "Mapping to Runvil" (the row "Mark output untrusted"); [master-glob.md](master-glob.md), "Print absolute VFS paths, bare, one per line, and leave out any name with a control character"; [master-grep.md](master-grep.md), "Mapping to Runvil" (the row "Output trust"); [master-str-replace.md](master-str-replace.md), "Name the cause and the next move in every refusal" | High - the standing plan already requires it |

## Shared facts, open decisions, and the skeleton of the evidence reports

### Shared facts

Six evidence reports restate the same Cursor infrastructure. These are the correct statements about Cursor's build, so you can check any report against them. What Runvil should do about each is in the cross-tool table above.

| Fact | The correct statement |
|---|---|
| Line-number format | Six-wide right-aligned, then a bare pipe, then the text with no space after it: `     1\|const x = 1;`. Five leading spaces, a digit, a pipe. No tab. The GPT-5 style is `L1:text`, reachable for `isGpt5Family`. Sparse mode, when `sparseLineNumbers` is an integer N, emits lines whose number is not a multiple of N with no prefix at all, and it forces both other styles off. The Codex style exists in `fH` but `gpt5CodexCatN` is unreachable in this build. |
| Read cap | 100,000, measured on JavaScript string length, which is UTF-16 code units, and applied *after* windowing. It errors rather than truncating: the record is `success` with `exceededLimit: true` and empty content, rendered with the error flag set. A byte-counting port diverges on CJK by up to 3x and on emoji by 2x, in both directions. |
| 8 MiB cut | `MAX_TEXT_SIZE = 8 * 1024 * 1024`, used as a *character* budget in the executor's slicing (`takeUtf8Window`, `appendBounded`) and as a *byte* threshold in `readWholeTextFile`'s `stats.size > MAX_TEXT_SIZE` refusal. The slice sets `truncated: true` and nothing renders it, so the cut is silent. These are two different comparisons on two different units at the same number, which is the easiest thing in the whole read path to get wrong. |
| Lock ordering | Keyed on the raw argument string, before any normalization, so two spellings of one path do not serialize. For Read's retry-on-miss the lock is released *before* the wait and re-acquired inside the retry, because the wait is for mutating calls that need the same key. Glob takes no lock at all and is absent from the mutating set. |
| Two ripgrep builders | `buildArgs` is the one Grep and Glob both use. `ripwalk` is a separate file-walking client neither tool reaches. They disagree on three defaults: `buildArgs` never passes `--no-require-git`, always passes `--follow`, and pushes `--case-sensitive` unless `caseInsensitive` is exactly true; `ripwalk` always passes `--no-require-git`, follows symlinks only when asked, and defaults `caseSensitive` to false. Do not describe "Cursor's ripgrep invocation" in the singular. |
| The pi family | A second complete surface in the same bundle: `pi_read`, `pi_bash`, `pi_edit`, `pi_write`, `pi_grep`, `pi_find`, `pi_ls`, registered from 4556823 to 4563905, each with its own proto message pair, and all seven rendering through one function that pulls a plain string out of `output`, `error`, or `reason` and returns `Pi tool returned no result.` when none is present. There is no `pi_delete`; deletion on that surface is `pi_bash` with `rm`. `pi_edit` takes an array of edits applied atomically against one snapshot, which is a better contract than `StrReplace`'s single pair, but its fuzzy path applies whole-file NFKC normalization and rewrites untouched lines, which you must not copy. |

### Open decisions

The masters have decided most of these. [What the masters decided together](#what-the-masters-decided-together) holds each decision, its owning section and its confidence, and [Open items that belong to Vinnie](#open-items-that-belong-to-vinnie) holds what is still open. Each group below keeps only what a master left open, and points at the rows that answered the rest.

**Read shape**

- Decided: line numbers always on in a six-wide pipe, a byte cap that truncates with a trailer, the negative-offset asymmetry kept, one `\r` stripped from every line, and line pagination over a bounded `Access::read_range`. See the rows "Line-number format", "Read cap and window" and "Line model".
- Still open: the 100,000-byte figure and the 16 MiB ceiling are judgments, and no harness measured how models cope with numbered text.

**Edit matching**

- Decided: matching lives in the Pack and `Access::str_replace` stays for Lua; the line-trimmed fallback stays, with a note on success; Cursor's overlap behavior is kept and guarded; Cursor's success sentence is the prefix; Write is gated on a whole read and StrReplace is never gated. See "The read record and who writes it" and "Mode and approval behavior".
- Still open: the order of an `edits` array (low confidence), and a prompt that offers Write without Read.

**Search backend**

- Decided: the Pack walks with `Access::list` and `Access::read`, and a VFS search waits for a measured trigger; the hyphenated names stay with no aliases and no coercion; negative context is rejected; `-A` and `-B` override `-C` per side; the broad-glob guard and the five-entry cache are dropped. See "Argument errors and unknown parameters" and "List cap and paging notices".
- Still open: whether the Harness honors a yield, and when a search over 2 s on a large Windows tree forces the VFS search.

**Ignore handling**

- Decided: one shared Pack module, ignore rules always win, a directory the model names is searched, and no privacy rule exists in version one. See "Ignore and hidden-path policy".
- Still open: the `ignore` crate against a matcher of his own.

**Tool selection per model**

- Decided: one set and one wire name per tool, with no per-family variants. `Pack::render` can reshape the set later, and must drop `StrReplace` and `Write` together. From the pi design the masters took `literal`, an optional `edits` array (low confidence) and `contents` kept as Write's parameter name, and they did not take a default `head_limit`. See "The per-model tool set".
- Still open: a measured drop in a GPT-5-family model's edits would reopen the vendor split.
