Group: ED-12 Comments in the editor. Pass: 3. Date: 2026-10-25.

### ED-12.1
1. A comment thread opens as a box inside the text, under the commented line or range, when an extension supplies one, since neither stock nor Cursor has a built-in comment provider.
2. The thread header shows the thread label, or "Start discussion" while the thread has no comments yet, with a Collapse button.
3. Header buttons that the providing extension adds through `comments/commentThread/title` show beside Collapse, and right-clicking the header opens the menu from `comments/commentThread/title/context`.
4. Below the header the thread lists its comments in order, and right-clicking a comment opens the menu from `comments/commentThread/comment/context`.
5. Under the comments the thread shows a reply box, with the buttons from `comments/commentThread/context` and `comments/commentThread/additionalActions` below it.
6. Setting `comments.maxHeight` chooses whether the thread box scrolls or expands to fit, with values on and off, default on.
7. Setting `comments.collapseOnResolve` chooses whether a thread collapses by itself when it is resolved, with values on and off, default on.
8. A screen reader announces a thread as "Comment thread with {n} comments on lines {a} through {b}", or "on the entire document" for a whole-file thread.

### ED-12.2
1. Where a provider allows comments, the line gutter marks the commenting ranges, and hovering a line inside a range shows a "+" in the gutter.
2. Clicking the "+" opens a new-comment box under that line, headed "Start discussion", with a reply box that reads "Type a new comment".
3. Dragging along the gutter across several lines opens a new-comment box that covers those lines.
4. Running "Add Comment on Current Selection" (`workbench.action.addComment`) opens the new-comment box on the current selection, and `Ctrl+K Ctrl+Alt+C` does the same when the cursor is inside a commenting range.
5. The Command Palette lists "Add Comment on Current Selection" under Comments only when the cursor is inside a commenting range.
6. When no commenting range matches, an error notification reads "The cursor must be within a commenting range to add a comment."
7. When several comment providers match the same spot, a menu from the gutter click, or a pick list with the placeholder "Select Comment Provider" from the keyboard, lets you choose which provider gets the comment.
8. Where a provider does not allow a comment on the whole file, an error notification reads "File comments are not allowed on this file."
9. With editor commenting turned off, the gutter shows no "+" and no marked commenting ranges.

### ED-12.3
1. A line that has a comment thread shows a comment icon in the gutter.
2. An unresolved thread and a resolved thread show different icon looks.
3. A thread with a draft comment shows a third look, and the draft look wins over the unresolved and resolved ones.
4. Each thread also draws a mark on the overview ruler, with separate looks for resolved, unresolved and draft threads.
5. The colors `editorGutter.commentRangeForeground`, `editorGutter.commentGlyphForeground` and `editorGutter.commentUnresolvedGlyphForeground` tint the gutter mark for commenting ranges, the thread icon and the unresolved thread icon.
6. The colors `editorOverviewRuler.commentForeground` and `editorOverviewRuler.commentUnresolvedForeground` tint the overview ruler marks for resolved and unresolved threads.

### ED-12.4
1. Each comment shows the author, an avatar when the provider gives one, the time and the body as rendered markdown.
2. Setting `comments.useRelativeTime` chooses whether the time reads relative, like "1 day ago", or as a full date, with values on and off, default on.
3. The reply box reads "Reply..." on a thread that already has comments and "Type a new comment" on a new thread, unless the provider sets its own text.
4. Pressing `Ctrl+Enter` in the reply box or an edit box sends the comment (`editor.action.submitComment`).
5. Header buttons on each comment, such as Edit and Delete, come from the providing extension's `comments/comment/title` menu, so none show without a provider.
6. Editing a comment turns its text into an editable box, with the buttons from `comments/comment/context` below it and the buttons from `comments/comment/editorActions` beside it.
7. A comment can show emoji reactions that are toggled by clicking them, and a "Pick Reactions..." button opens a list to add more.
8. When toggling a reaction fails, an error message reads "Toggling the comment reaction failed".

### ED-12.5
1. Pressing `Escape` or `Shift+Escape` in a comment box or on a focused comment collapses that thread (`workbench.action.hideComment`).
2. Pressing `Ctrl+Escape` (`Alt+Backspace` on Windows) with the text editor focused collapses every visible comment thread.
3. When the thread holds unsent text, a dialog warns that collapsing will discard the unsubmitted comments and asks you to confirm, with a "Never ask me again" checkbox.
4. In Cursor the dialog reads "Collapsing a comment thread will discard unsubmitted comments. Do you want to collapse this comment thread?" with a Collapse button. [cursor only]
5. In stock the dialog reads "Collapsing this comment thread will discard unsubmitted comments. Are you sure you want to discard these comments?" with a Discard button. [stock only]
6. Cancelling the dialog keeps the thread open with the unsent text intact, and confirming with "Never ask me again" ticked sets `comments.thread.confirmOnCollapse` to `never`.
7. Setting `comments.thread.confirmOnCollapse` chooses whether the dialog shows, with values `whenHasUnsubmittedComments` and `never`, default `whenHasUnsubmittedComments`.

### ED-12.6
1. Pressing `Alt+F9` or `Shift+Alt+F9` jumps to the next or previous comment thread (`editor.action.nextCommentThreadAction`, `editor.action.previousCommentThreadAction`).
2. Pressing `Alt+F10` or `Shift+Alt+F10` jumps to the next or previous commented range, listed as "Go to Next Commented Range" and "Go to Previous Commented Range" (`editor.action.nextCommentedRangeAction`, `editor.action.previousCommentedRangeAction`).
3. Pressing `Ctrl+K Ctrl+Alt+Down` or `Ctrl+K Ctrl+Alt+Up` jumps to the next or previous range where you can add a comment, listed as "Go to Next Commenting Range" and "Go to Previous Commenting Range" (`editor.action.nextCommentingRange`, `editor.action.previousCommentingRange`).
4. Running "Focus Comment on Current Line" (`workbench.action.focusCommentOnCurrentLine`) puts focus in the thread on the cursor line.
5. When the cursor line has no comment, "Focus Comment on Current Line" shows an error notification reading "The cursor must be on a line with a comment to focus the comment".
6. All of these commands are listed in the Command Palette under Comments.

### ED-12.7
1. Running "Collapse All Comments" (`workbench.action.collapseAllComments`) collapses every comment thread in the editors.
2. Running "Expand All Comments" (`workbench.action.expandAllComments`) expands every comment thread.
3. Running "Expand Unresolved Comments" (`workbench.action.expandUnresolvedComments`) expands only the unresolved threads.
4. Running "Toggle Editor Commenting" (`workbench.action.toggleCommenting`) hides or shows the comment gutter icons and threads in all editors, and it is listed only when the workspace has commenting.
5. Setting `comments.visible` chooses whether the comment gutter and threads show in editors by default, with values on and off, default on.
6. All four commands are listed in the Command Palette under Comments.

### ED-12.8
1. In a diff editor, comment gutter icons and comment threads show on both the original side and the modified side.
2. Comment icons and threads show in both the side by side view and the inline view.
3. Opening a thread from elsewhere reveals it on the side of the diff that owns it, original or modified.
4. Setting `diffEditor.renderSideBySide` chooses side by side or inline view, with values on and off, default on, and switching it makes the editor re-check the commenting ranges so the comment marks follow the new layout.

## Unclear

- ED-12.3: the Pass 2 feature block writes the color names without dots, which are the message keys. The real color ids from source are `editorGutter.commentRangeForeground`, `editorGutter.commentGlyphForeground`, `editorGutter.commentUnresolvedGlyphForeground`, `editorOverviewRuler.commentForeground` and `editorOverviewRuler.commentUnresolvedForeground`, and the pieces use those. Source also has two draft colors, `editorGutter.commentDraftGlyphForeground` and `editorOverviewRuler.commentDraftForeground`, which the feature block does not list and which were not searched for in the Cursor bundle.
- ED-12.6: `Alt+F9` and `Shift+Alt+F9` are also bound by ED-13.5 for the uncovered line jumps, with the same key weight in 1.128.0 source, so which command answers depends on what is available in the file.
- ED-12.2: the whole-file comment path is only reachable through the add comment command's arguments, so no on-screen entry for it was found and the piece states only the visible error message.
- ED-12.1: `comments.maxHeight` is described only as "whether the comments widget scrolls or expands", so the piece does not say which value does which.
